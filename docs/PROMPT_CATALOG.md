## 1. Protocol Prompt Injections

> Generated by protocol expanders and appended to step.prompt_template during `apply_protocol`. End up inside `<task>` tags at runtime.

### 1.1 Decomposition Protocol — `decomp_prompt()`

**File:** `src/server/hub/protocols/prompt_gen.rs:7-59`
**Category:** User prompt injection
**Purpose:** Instructs LLM to decompose a task into subtasks and route each to specialist agents (fan-out 1→N).

```
## Task Decomposition Protocol

You must decompose the given task and assign subtasks to the available agents below.
You may assign MULTIPLE tasks to the same port — each will be executed independently.
Respond with a JSON array where each item has a "port" and "content" field.

### Available Agents

- **Port: "{port_name}"** ({agent_name}) — {description}
  Tools: {tool1}, {tool2}

### Output Format

```json
[
  {"port": "{port_name}", "content": {...task details...}},
  ...
]
```
```

### 1.2 Routing Protocol — `route_prompt()`

**File:** `src/server/hub/protocols/prompt_gen.rs:63-92`
**Category:** User prompt injection
**Purpose:** Instructs LLM to examine input and route to exactly ONE downstream agent (conditional switch 1→1-of-N).

```
## Routing Protocol

Examine the input and route it to exactly ONE of the available agents below.
Respond with a JSON object containing a "port" and "content" field.

### Available Agents

- **Port: "{port_name}"** ({agent_name}) — {description}
  Tools: {tool1}, {tool2}

### Output Format

```json
{"port": "<chosen_port>", "content": {...task details...}}
```
```

### 2.2 Schema Enhancement Filter

**File:** `src/server/hub/engine/filters/schema_enhancement/mod.rs:40-49`
**Category:** System prompt augmentation
**Purpose:** Adds explicit anti-patterns to prevent common LLM JSON output mistakes.

```
<output_rules>
- Output ONLY the raw JSON object. No markdown code fences (```), no commentary.
- Do NOT wrap your response in ```json ... ```. The consumer parses raw JSON directly.
- Do NOT include any text before or after the JSON object.
- Do NOT include explanatory sentences like "Here is the JSON:".
- If a field is optional and you have no value, use null rather than omitting it.
- Every string value must be properly escaped JSON.
</output_rules>
```

### 2.3 Schema Validation Retry Filter

**File:** `src/server/hub/engine/filters/schema_validation_retry/mod.rs:45-75`
**Category:** Retry feedback prompt
**Purpose:** Sends corrective feedback when LLM output doesn't match expected schema.

**Primitive value error:**
```
Your response parsed as JSON but is a primitive value ({type}).
You MUST respond with a JSON object or array matching the schema.
Output ONLY the raw JSON, no other text.
```

**Markdown fence error:**
```
Your JSON content is valid but you wrapped it in markdown code fences (```json ... ```).
Output ONLY the raw JSON object with no surrounding text or markdown.
```

**Parse error:**
```
Your response is not valid JSON. Parse error: {error}

You MUST respond with ONLY a valid JSON object matching the schema.
No markdown, no explanation, no code fences. Just the raw JSON.
```

### 2.6 Debate Verification Filter

**File:** `src/server/hub/engine/filters/debate_verification/mod.rs`

**Verifier system prompt (lines 96-119):**

## Verification Role

Your expertise: {agent_name}.

IMPORTANT:
- Form your OWN independent assessment. Do not assume the response is correct.

- Be specific and constructive — cite exact issues with line references or quotes.

Respond with JSON:
{
  "approved": true,
  "issues": [
    {
      "severity": "high",
      "description": "Specific issue description",
      "suggestion": "How to fix it"
    }
  ]
}

## 6. Haiku Utility Prompts

> Fast-model (Haiku) calls for auxiliary tasks like file reading, summarization, title generation.

### 6.1 File Reading / Code Extraction

**File:** `src/server/tools/mod.rs:496-517`
**Category:** System prompt / utility
**Purpose:** Fast model extracts relevant code sections from source files.

```
You are a code reader. Given a source file, extract and return the most relevant content.
Include function signatures, struct/type definitions, key logic, and imports.
Use the original code when possible — quote exact lines for precision.
If a focus area is specified, prioritize content related to it.
Be concise but preserve technical accuracy. Do not add commentary.
```
