# Ticket 22.4: Agent Worker Mode

> Standalone binary mode where nexor runs as a worker inside a container, connecting back to the host orchestrator.

## Goal

`nexor --worker --orchestrator-url ws://host:3000/ws/worker` starts the binary in worker mode. The worker registers with the orchestrator, receives task assignments, executes them using local file/git/test operations, and reports results back.

## File Changes

| File | Change |
|------|--------|
| `src/worker.rs` | **New** — Worker mode entry point, WS connection, task execution loop |
| `src/cli.rs` | Add `--worker` and `--orchestrator-url` CLI flags |
| `src/main.rs` | Route to worker mode when `--worker` is set |

## Slices

### 22.4.1: CLI flags for worker mode

Add to the existing CLI parser:

```rust
/// Run as an agent worker (used inside containers)
#[arg(long)]
worker: bool,

/// Orchestrator WebSocket URL to connect to
#[arg(long, default_value = "ws://localhost:3000/ws/worker")]
orchestrator_url: String,

/// Agent ID assigned by the orchestrator
#[arg(long)]
agent_id: Option<String>,
```

Update `main.rs` to branch: if `--worker`, call `worker::run()` instead of starting the server.

**Test**: CLI parsing accepts `--worker --orchestrator-url ws://example.com/ws`.

### 22.4.3: Task receive and execution

Worker receives task assignments and executes them:

```rust
// Message types
enum WorkerMessage {
    Register { agent_id: String, capabilities: Vec<String> },
    TaskAssignment { task_id: Uuid, description: String, branch: String },
    TaskProgress { task_id: Uuid, status: String, output: String },
    TaskComplete { task_id: Uuid, result: TaskResult },
    TaskFailed { task_id: Uuid, error: String },
    Heartbeat,
}
```

The worker uses the existing `ExecutionContext`, `FileOps`, `GitOps`, and `TestRunner` to do actual work — these all operate on the mounted `/workspace`.

**Test**: Worker processes a task assignment message and sends progress updates.

### 22.4.4: Health check endpoint

Minimal HTTP server on port 3001 inside the container:

```rust
// GET /health → 200 OK { "status": "ready", "agent_id": "..." }
```

Uses a lightweight axum server (the dependency already exists).

**Test**: Health endpoint returns 200 with agent_id.

### 22.4.5: Graceful shutdown

Worker handles SIGTERM (from `docker stop`):
- Finish current operation if possible
- Send `TaskFailed` with reason "container_shutdown" if mid-task
- Close WS connection cleanly

**Test**: Shutdown handler sends failure message for in-progress task.
