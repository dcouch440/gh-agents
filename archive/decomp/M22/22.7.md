# Ticket 22.7: Cleanup, Monitoring & Health

> Ensure containers and worktrees are properly cleaned up on completion, failure, crash, and server restart. Health monitoring detects stuck or dead containers.

## Goal

No orphaned containers or worktrees. The system recovers gracefully from crashes, detects unhealthy containers, and provides observability into container state.

## Slices

### 22.7.1: Startup cleanup

On server start, scan for orphaned resources:

```rust
pub async fn recover_on_startup(&mut self) -> Result<RecoveryReport, ContainerPoolError>;

pub struct RecoveryReport {
    pub orphaned_containers_removed: usize,
    pub orphaned_worktrees_removed: usize,
}
```

- Find Docker containers matching `nexor-agent-*` pattern
- Find worktrees in `.nexor/worktrees/` that aren't tracked
- Stop and remove orphaned containers
- Remove orphaned worktrees

**Test**: Creates orphaned container/worktree entries, verify cleanup removes them.

### 22.7.2: Health monitoring loop

Background task that periodically checks container health:

```rust
pub async fn monitor_loop(
    pool: Arc<Mutex<ContainerPool>>,
    interval: Duration,
) -> Result<(), ContainerPoolError>;
```

- Poll every 30s (configurable)
- Check each container's health endpoint
- If unhealthy for 3 consecutive checks: kill and requeue task
- Log warnings for containers approaching memory/CPU limits

**Test**: Unhealthy container triggers cleanup after threshold.

### 22.7.3: Shutdown drain

On server shutdown (SIGTERM), gracefully drain all containers:

```rust
pub async fn drain_all(&mut self, timeout: Duration) -> Result<DrainReport, ContainerPoolError>;

pub struct DrainReport {
    pub graceful_stops: usize,
    pub force_kills: usize,
    pub worktrees_removed: usize,
}
```

- Signal each worker to finish current operation
- Wait up to timeout
- Force kill remaining
- Remove all worktrees

**Test**: Drain stops all containers and removes worktrees.
