# Ticket 16.2: User Accounts & Org Model

> Real user accounts, organizations, memberships, roles, and invitations.

## Goal

Users have real identities. Organizations group users into teams with roles. Invitations let you bring teammates in. This replaces the single-password auth from M10.5.

**Checkpoint**: Can register, create an org, invite a teammate via link, teammate joins with a role, both users see the same org context.

---

## Context

Current auth is a single password with JWT — no user identity. SaaS requires real users who belong to organizations.

**Key files**:
- `src/server/auth.rs` — Current auth (rewrite)
- `src/db/mod.rs` — Database queries
- `src/server/api.rs` — API endpoints
- `migrations/` — New Postgres migrations

**Dependencies**:
- Requires 16.1 (Postgres Migration) complete

## Slices

### Slice 16.2.1: User Table & Registration

**Do this**:
- Create `users` table: `id` (UUID), `email` (UNIQUE), `display_name`, `avatar_url`, `password_hash` (nullable — GitHub OAuth users won't have one), `github_id` (nullable), `created_at`, `updated_at`
- `POST /api/auth/register` — email + password registration
  - Validate email format, password strength
  - Hash password with argon2
  - Return JWT with user_id embedded
- `POST /api/auth/login` — email + password login
  - Return JWT with user_id and org_id
- Update JWT to include `user_id`, `org_id`, `role`

**Create/modify**:
- `migrations/` — users table
- `src/server/auth.rs`
- `src/server/api.rs`

### Slice 16.2.3: Memberships & Roles

**Do this**:
- Create `org_memberships` table: `org_id`, `user_id`, `role` (owner/admin/member/viewer), `joined_at`
- Org creator gets `owner` role automatically
- `GET /api/orgs/:id/members` — List members with roles
- `PATCH /api/orgs/:id/members/:user_id` — Change role (owner/admin only)
- `DELETE /api/orgs/:id/members/:user_id` — Remove member (owner/admin only, can't remove owner)
- Role hierarchy: owner > admin > member > viewer

### Slice 16.2.4: Invitation System

**Do this**:
- Create `invitations` table: `id` (UUID), `org_id`, `email` (nullable), `invite_code` (UNIQUE), `role` (default: member), `invited_by` (FK users), `accepted_at` (nullable), `expires_at`, `created_at`
- `POST /api/orgs/:id/invitations` — Create invitation (returns link with invite_code)
  - Can specify email (targeted) or generate a shareable link (open)
  - Set role for invitee, set expiry (default 7 days)
- `GET /api/orgs/:id/invitations` — List pending invitations
- `DELETE /api/orgs/:id/invitations/:invite_id` — Revoke invitation
- `POST /api/invitations/:code/accept` — Accept invitation
  - If user is logged in, add to org
  - If not logged in, redirect to register/login first, then accept

**Create/modify**:
- `migrations/` — invitations table
- `src/server/api.rs`
