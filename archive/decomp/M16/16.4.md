# Ticket 16.4: Cloud Repo Management

> Server-side repo clones per org with sandboxed storage, GitHub sync, and disk quotas.

## Goal

Repos live on the server, not on the user's local machine. Import from GitHub clones to server storage. Each org gets isolated storage. Repos stay in sync with GitHub via pull/push.

**Checkpoint**: Import a repo from GitHub, server clones it, file tree loads in the editor, changes can be pushed back.

---

## Context

M15.1 assumed repos are local paths. In SaaS mode, repos are cloned to server-managed storage. The file/git operations still work the same — they just operate on server-side paths that users never see directly.

**Key files**:
- `src/execution/files.rs` — File operations
- `src/execution/git.rs` — Git operations
- `src/server/api.rs` — API endpoints
- `src/db/mod.rs` — Database queries

**Dependencies**:
- Requires 16.1 (Postgres), 16.2 (Orgs), 16.3 (GitHub OAuth)

### Slice 16.4.2: Repo Clone from GitHub

**Do this**:
- `POST /api/repos/import` — Clone a GitHub repo to server storage
  - Body: `{ github_full_name: "owner/repo" }`
  - Uses the user's stored GitHub access token for authentication
  - Clones to `{storage}/{org_id}/repos/{repo_id}/`
  - Creates repo record in DB with `source: github`, `github_full_name`, `server_path`
  - Returns immediately with repo ID, clone runs in background
- Broadcast clone progress via WebSocket: `clone_started`, `clone_progress`, `clone_complete`, `clone_failed`

### Slice 16.4.3: Repo Sync (Pull/Push)

**Do this**:
- `POST /api/repos/:id/sync` — Pull latest from GitHub remote
  - Uses stored GitHub token for auth
  - Handles merge conflicts (report to user, don't auto-resolve)
- `POST /api/repos/:id/push` — Push commits to GitHub
  - Requires user's GitHub token with repo write access
- Background sync: configurable auto-pull interval per repo (default: off)
- Broadcast sync events via WebSocket

### Slice 16.4.5: Repo Access Scoping
