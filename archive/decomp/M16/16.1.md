# Ticket 16.1: Postgres Migration

> Replace SQLite with Postgres for multi-tenant, multi-user persistence.

## Goal

All data persistence moves from SQLite to Postgres. Connection pooling, all migrations rewritten, all queries updated, configurable via `DATABASE_URL`.

**Checkpoint**: `cargo test` passes with Postgres, server starts and connects to Postgres, all existing functionality works.

---

## Context

SQLite is single-writer and file-based — fine for local, breaks under concurrent multi-user SaaS load. Postgres gives us proper concurrency, connection pooling, and a path to read replicas later.

**Key files**:
- `src/db/mod.rs` — All database operations
- `migrations/` — All migration files (rewrite for Postgres syntax)
- `src/server/state.rs` — AppState holds DB connection
- `Cargo.toml` — Swap deps

**Dependencies**: None — this is the first M16 ticket

### Slice 16.1.2: Rewrite Migrations for Postgres

**Do this**:
- Convert all SQLite migrations (001-006) to Postgres syntax:
  - `TEXT` types stay, `BOOLEAN` becomes proper boolean
  - `DATETIME` becomes `TIMESTAMPTZ`
  - `AUTOINCREMENT` becomes `SERIAL` or use UUIDs
  - Add proper foreign key constraints
- Use sqlx migrations (`sqlx migrate`) instead of manual migration runner
- Ensure migrations run idempotently

**Create/modify**:
- `migrations/` — Rewrite all `.sql` files for Postgres

**Verify**:
- [ ] `sqlx migrate run` succeeds on fresh Postgres database
- [ ] Schema matches original intent

### Slice 16.1.3: Rewrite Core Queries
