# Ticket 17.3: Connection Pool & Init Rewrite

> Replace `SqlitePool` with `PgPool` and switch from custom migration runner to `sqlx::migrate!`.

## Goal

The application connects to Postgres via `PgPool`, runs migrations on startup with `sqlx::migrate!`, and all pool-related code compiles.

**Checkpoint**: `cargo check` passes for the db module, app starts and connects to Postgres.

---

## Context

The current `db/mod.rs` creates a `SqlitePool`, runs migrations by splitting SQL files on `;`, and returns the pool. This needs to become `PgPool` with `sqlx::migrate!`.

**Key files**:
- `src/db/mod.rs` — Pool creation and initialization
- `src/db/migrations.rs` — Custom migration runner (to be replaced)

**Dependencies**: 17.2 (migrations must exist in Postgres format)

---

## Slices

### Slice 17.3.1: Pool Type Swap

**Do this**:
- Change `SqlitePool` to `PgPool` in `src/db/mod.rs`
- Update `init_db()` to accept `DATABASE_URL` string instead of file path
- Create pool with `PgPoolOptions::new().max_connections(10).connect(&database_url)`
- Update the return type from `SqlitePool` to `PgPool`

**Verify**:
- [ ] `src/db/mod.rs` compiles with `PgPool`
- [ ] Pool connects to Postgres on startup

---

### Slice 17.3.2: Replace Custom Migration Runner

**Do this**:
- Remove the custom migration runner in `src/db/migrations.rs` (the one that reads SQL files and splits on `;`)
- Replace with `sqlx::migrate!().run(&pool).await?`
- Ensure migrations directory path is correct for `sqlx::migrate!` macro
- Delete `src/db/migrations.rs` if it only contained the custom runner

**Verify**:
- [ ] Migrations run automatically on app startup
- [ ] `sqlx migrate info` shows all migrations applied
- [ ] No custom SQL splitting logic remains

---

### Slice 17.3.3: Database Type Exports

**Do this**:
- Update `src/db/mod.rs` exports: `pub use sqlx::PgPool;` (or re-export as `DbPool` type alias)
- Update `src/lib.rs` if it re-exports db types
- Ensure all downstream code can import the pool type

**Verify**:
- [ ] `cargo check` passes for the entire db module
- [ ] Pool type is accessible from other modules
