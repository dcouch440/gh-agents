# Ticket 23.4: Planner & Scheduler Integration

> Wire gate creation into decomposition and gate checking into task assignment.

## Goal

The planner creates gates after decomposition (based on config toggles). The scheduler checks gate status before assigning work — unresolved ancestor gates block descendants.

**Checkpoint**: Decompose a ticket → gates created for enabled levels → scheduler skips tasks with unresolved gates → resolve gate → scheduler assigns task.

---

## Context

The planner (`src/orchestration/planner.rs`) currently decomposes tickets into slices and tasks. It needs to also create gate records when config toggles are on.

The scheduler (`src/orchestration/scheduler.rs`) currently checks dependencies and agent availability. It needs an additional gate-clear check.

**Key files**:
- `src/orchestration/planner.rs` — Add gate creation after decomposition
- `src/orchestration/scheduler.rs` — Add gate checking before assignment
- `src/types/config.rs` — Gate toggle fields (from 23.1)

**Dependencies**:
- 23.3 (gate service)

## Slices

### Slice 23.4.1: Planner Gate Creation

**Do this**:
- Add `GateService` as a dependency of the Planner (or pass config + gate repo)
- After `decompose()` produces slices and tasks, create gates for each level where the config toggle is enabled
- Milestone gates: one gate per milestone (from PRD milestones JSONB)
- Slice gates: one gate per vertical slice
- Task gates: one gate per task

**Modify `src/orchestration/planner.rs`**:
```rust
// After decomposition output is produced:
if config.approval_gates.is_gate_enabled(GateLevel::Slice) {
    for slice in &output.slices {
        gate_service.create_gate(GateLevel::Slice, slice.id.0, AgentTier::Worker).await?;
    }
}
if config.approval_gates.is_gate_enabled(GateLevel::Task) {
    for task in &output.tasks {
        gate_service.create_gate(GateLevel::Task, task.id.0, task.assigned_tier).await?;
    }
}
```

**Verify**:
- [ ] Decomposition with `milestone_gates = true` creates milestone gates
- [ ] Decomposition with `slice_gates = true` creates slice gates
- [ ] Decomposition with `task_gates = false` creates no task gates
- [ ] Gate agent_tier matches the work assignment tier

### Slice 23.4.2: Scheduler Gate Check

**Do this**:
- Before assigning a task, check that all ancestor gates are clear
- Check the task's own gate (if exists)
- Check the parent slice's gate (if exists)
- Check the parent milestone's gate (if exists)
- If any ancestor gate is unresolved, skip the task (leave it in queue)

**Modify `src/orchestration/scheduler.rs`**:
```rust
// In the task assignment logic (tick() or similar):
async fn can_assign_task(&self, task: &Task) -> Result<bool> {
    // Check task-level gate
    if !self.gate_service.is_gate_clear(GateLevel::Task, task.id.0).await? {
        return Ok(false);
    }
    // Check slice-level gate
    if let Some(slice_id) = task.slice_id {
        if !self.gate_service.is_gate_clear(GateLevel::Slice, slice_id.0).await? {
            return Ok(false);
        }
    }
    // Check milestone-level gate (requires looking up slice → ticket → milestone)
    // Implementation depends on how milestone IDs are tracked
    Ok(true)
}
```

**Verify**:
- [ ] Task with pending gate is not assigned
- [ ] Task with resolved gate is assigned normally
- [ ] Task with skipped ancestor gate is assigned
- [ ] Task with no gates is assigned normally
