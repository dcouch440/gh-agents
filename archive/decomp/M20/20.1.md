# Ticket 20.1: WebSocket & Feed Types

> Add TypeScript types for the WebSocket protocol and feed data models, mirroring the Rust backend's `ws.rs` types.

## Goal

All WS message shapes and feed data types are defined and exported from `api/types.ts`.

**Checkpoint**: Types compile, other tickets can import them.

---

## Context

The backend (`src/server/ws.rs`) defines the WS protocol:
- Client sends `Subscribe { channels }` and `Unsubscribe { channels }`
- Server sends `Subscribed`, `Feed { data }`, `TaskUpdate { data }`, `AgentUpdate { data }`, `Error { message }`
- `FeedUpdate` has: `id`, `agent_id`, `content`, `item_type`, `timestamp`

**Key files**:
- `cli/src/api/types.ts` — Add WS + feed types here
- `src/server/ws.rs` — Backend reference for type shapes

**Dependencies**: None

---

## Slices

### Slice 20.1.1: WebSocket Protocol Types

**Do this**:
- Add `WsClientMessage` union type: `WsSubscribeMessage | WsUnsubscribeMessage`
- Add `WsServerMessage` discriminated union with `type` field: `subscribed`, `feed`, `task_update`, `agent_update`, `error`
- Types must match the JSON shapes from `ws.rs` exactly

**Add to `cli/src/api/types.ts`**:
```typescript
export interface WsSubscribeMessage {
  type: 'subscribe';
  channels: string[];
}
export interface WsUnsubscribeMessage {
  type: 'unsubscribe';
  channels: string[];
}
export type WsClientMessage = WsSubscribeMessage | WsUnsubscribeMessage;

export type WsServerMessage =
  | { type: 'subscribed'; channels: string[] }
  | { type: 'feed'; data: FeedUpdate }
  | { type: 'task_update'; data: TaskUpdate }
  | { type: 'agent_update'; data: AgentUpdate }
  | { type: 'error'; message: string };
```
