# Ticket 20.2: WebSocket Client

> Create a reconnecting WebSocket client that connects to the backend, subscribes to channels, and emits parsed messages.

## Goal

A `NexorWsClient` class that manages the WS connection lifecycle with auto-reconnect, exponential backoff, and typed message events.

**Checkpoint**: Client connects to backend WS, receives feed updates, reconnects after disconnect.

---

## Context

Backend WS endpoint is at `/ws`. On connect, client must send a `subscribe` message for desired channels (`feed`, `tasks`, `agents`). Server responds with `subscribed` confirmation.

**Key files**:
- `cli/src/api/ws.ts` — New file
- `cli/src/api/ws.test.ts` — New file
- `cli/src/api/types.ts` — Import WS types from 20.1

**Dependencies**: 20.1

---

## Slices

### Slice 20.2.1: Basic WebSocket Connection

**Do this**:
- Create `cli/src/api/ws.ts`
- `NexorWsClient` extends `EventEmitter`
- Constructor takes `baseUrl` (REST URL) and `token`
- Derive WS URL: `http://` → `ws://`, `https://` → `wss://`, append `/ws`
- `connect()` opens WebSocket, sets `onopen`/`onmessage`/`onclose`/`onerror`
- On open: send `{ type: 'subscribe', channels: ['feed', 'tasks', 'agents'] }`
- `disconnect()` cleanly closes
- `getStatus()` returns `'connecting' | 'connected' | 'disconnected'`

**Verify**:
- [ ] Compiles with `npx tsc --noEmit`

---

### Slice 20.2.2: Message Parsing & Events

**Do this**:
- On `onmessage`: parse JSON as `WsServerMessage`
- Emit `'message'` event with parsed message
- Emit `'status'` event on status changes (connecting/connected/disconnected)
- Emit `'error'` event on parse failures or WS errors
- Silently ignore malformed messages (log to console.error)

**Verify**:
- [ ] Unit test: mock WebSocket, verify events emitted for each message type

---

### Slice 20.2.3: Reconnect with Exponential Backoff

**Do this**:
- On `onclose` or `onerror`: schedule reconnect
- Initial delay: 2000ms, double each attempt, cap at 30000ms
- Reset delay on successful connection (`subscribed` message received)
- `disconnect()` cancels pending reconnect timer
- Track reconnect state to avoid duplicate timers

**Verify**:
- [ ] Unit test: verify backoff timing (2s, 4s, 8s, 16s, 30s, 30s)
- [ ] Unit test: verify timer cancelled on manual disconnect

---

### Slice 20.2.4: Token in Connection

**Do this**:
- Pass auth token as query param: `ws://host/ws?token=<token>`
- Or pass in WS protocol header if backend supports it
- Check backend `ws.rs` for expected auth mechanism and match it

**Verify**:
