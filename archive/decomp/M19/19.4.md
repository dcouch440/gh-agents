# Ticket 19.4: ToolCallBlock Component

> The core UI component — a collapsible block that renders a single tool invocation with header, status, and expandable output.

## Goal

`ToolCallBlock` renders one tool call as a compact, interactive block. The header shows: tool icon, tool name, key argument (file path or command), status indicator, and duration. The body is collapsible and renders the tool's output using the appropriate renderer. It looks like a Claude Code tool call in a terminal — structured, scannable, and information-dense without being noisy.

**Checkpoint**: A completed `Read` tool call renders as: `[ Read ] src/main.rs — 42ms` with a chevron that expands to show syntax-highlighted file content. A running `Bash` call shows: `[ Bash ] cargo test ●` with a pulsing dot.

## Slices

### Slice 19.4.1: Block Layout & Header

**Do this**:
- Create `ToolCallBlock` component accepting `toolCall: ToolCall` prop
- Render block structure:
  ```
  ┌─ [icon] ToolName  argument-summary          duration  [chevron]
  │  (collapsible body — output content)
  └─
  ```
- Header elements:
  - **Left border**: 2px solid, color varies by tool type (see design language in README)
  - **Icon**: Small icon per tool type (use lucide-react: `FileText` for Read, `FilePlus` for Write, `FileEdit` for Edit, `Search` for Glob/Grep, `Terminal` for Bash, `GitBranch` for Git, `Play` for RunTests)
  - **Tool name**: Monospace, `--color-text-primary`, 0.8125rem
  - **Argument summary**: Truncated key argument — file path for Read/Write/Edit, pattern for Glob/Grep, command for Bash. `--color-text-secondary`. Max 60 chars with ellipsis.
  - **Duration badge**: `--color-text-tertiary`, monospace, right-aligned. Show "..." while running.
  - **Chevron**: Right side, rotates 90deg when expanded. `--color-text-tertiary`.
- Background: `--color-bg-secondary`
- Border radius: 0.25rem
- Margin bottom: 0.25rem (tight stacking)
- Hover: background to `--color-bg-tertiary`

**Verify**:
- [ ] Block renders with correct tool icon and name
- [ ] Argument summary shows file path for Read, pattern for Grep, command for Bash
- [ ] Duration shows in ms (or "1.2s" for > 999ms)
- [ ] Hover state visible
- [ ] Left border color matches tool type

### Slice 19.4.2: Collapse/Expand Behavior

**Do this**:
- Header is clickable — toggles body visibility
- Body hidden by default for successful tool calls
- Body visible by default for:
  - Failed tool calls (`status === "failed"`)
  - Currently running tool calls (`status === "running"`)
- Chevron rotates with 0.15s CSS transition
- Body uses `max-height` transition (0.2s) for smooth expand/collapse
  - Calculate max-height from content, cap at 400px with overflow-y scroll
- Store expanded/collapsed state locally in component (not in Zustand — per-instance)

**Verify**:
- [ ] Click header → body toggles
- [ ] Successful calls start collapsed
- [ ] Failed calls start expanded
- [ ] Running calls start expanded (body shows spinner/placeholder)
- [ ] Chevron animates smoothly
- [ ] Body scroll works when content exceeds 400px

### Slice 19.4.3: Status Indicators

**Do this**:
- Running state:
  - Pulsing accent-colored dot (reuse `StatusDot` with `active` + pulse)
  - Duration shows elapsed time, updating every second via `setInterval`
  - Argument summary may show partial info
- Completed state:
  - No dot (or subtle success checkmark if space permits)
  - Duration shows final value
  - Chevron visible for expand
- Failed state:
  - Red dot (`StatusDot` with `error`)
  - Error message shown in header after argument summary: `--color-status-error`, italic
  - Left border red
  - Body auto-expanded showing error details

**Verify**:
- [ ] Running → pulsing dot, live timer
- [ ] Completed → static, shows final duration
- [ ] Failed → red indicators, error message visible in header
- [ ] Transition from running → completed updates smoothly (no flicker)

### Slice 19.4.4: Argument Summary Extraction

**Do this**:
- Create helper `getArgumentSummary(toolName: string, args: Record<string, unknown>): string`:
  - `Read` → `args.path` (e.g., `"src/main.rs"`)
  - `Write` → `args.path`
  - `Edit` → `args.path`
  - `Glob` → `args.pattern` (e.g., `"**/*.rs"`)
  - `Grep` → `args.pattern` (e.g., `"fn main"`)
  - `Bash` → `args.command`, truncated to 60 chars (e.g., `"cargo test --lib..."`)
  - `GitStatus` → (empty)
  - `GitDiff` → `args.staged ? "staged" : "unstaged"`
  - `GitCommit` → first 50 chars of `args.message`
  - `RunTests` → `args.pattern || "all tests"`
- Truncate all summaries to 60 chars with `"..."` suffix

**Verify**:
- [ ] Each tool type produces a meaningful one-line summary
- [ ] Long paths/commands truncated with ellipsis
- [ ] Missing args → empty string (no crash)

### Slice 19.4.5: Output Delegation

**Do this**:
- When body is expanded, render the appropriate output component based on `toolCall.output.type`:
  - `"text"` → `<TextOutput content={output.content} />`  (19.5)
  - `"file_list"` → `<FileListOutput files={output.files} />`  (19.5)
  - `"search_matches"` → `<SearchMatchesOutput matches={output.matches} />`  (19.5)
  - `"diff"` → `<DiffOutput path={output.path} oldContent={output.oldContent} newContent={output.newContent} />`  (19.5)
  - `"empty"` → nothing (body stays collapsed or shows "No output")
  - `undefined` (running) → `<LoadingOutput />` (simple spinner + "Executing...")
- If output type is unknown → fall back to `<TextOutput content={JSON.stringify(output)} />`
- If `truncated` is true, show a subtle note below the output: "Output truncated — showing first N items"

**Verify**:
- [ ] Each output type delegates to the correct renderer
- [ ] Running call shows loading state
- [ ] Unknown output type falls back gracefully
- [ ] Truncation note visible when `truncated: true`
