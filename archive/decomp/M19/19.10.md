# Ticket 19.10: Polish, Animations & Performance

> Final pass to make tool execution UI feel smooth, fast, and delightful — optimized rendering, refined animations, keyboard shortcuts, and edge-case handling.

## Goal

The tool execution UI feels as smooth as Claude Code. Animations are buttery. Rapid tool calls don't cause jank. Large outputs render without lag. Keyboard shortcuts let power users navigate tool calls efficiently. Error states are clear and recoverable.

**Checkpoint**: Agent fires 20 tool calls in 5 seconds — UI stays smooth at 60fps. User presses `j`/`k` to navigate between tool call blocks, `Enter` to expand, `Esc` to collapse. A tool call that returns 10,000 lines renders instantly with virtualization.

## Slices

### Slice 19.10.1: Render Performance

**Do this**:
- Virtualize long lists using `react-window` or `@tanstack/react-virtual`:
  - `TextOutput`: virtualize lines when content exceeds 200 lines
  - `FileListOutput`: virtualize when >50 files
  - `SearchMatchesOutput`: virtualize when >20 matches
  - Agent activity timeline: virtualize when >30 tool calls
- Memoize `ToolCallBlock` with `React.memo` — only re-render when `toolCall` object changes
- Memoize output renderers — `TextOutput`, `DiffOutput`, etc.
- Use `useDeferredValue` for search/filter inputs that trigger re-renders
- Profile with React DevTools and ensure no unnecessary re-renders during streaming

**Verify**:
- [ ] 100 tool calls in AgentsPage → smooth scroll, no jank
- [ ] 10,000-line file output → instant render with virtualization
- [ ] Rapid tool events (20/second) → no dropped frames
- [ ] React DevTools shows no unnecessary re-renders

### Slice 19.10.2: Animation Refinement

**Do this**:
- ToolCallBlock expand/collapse:
  - Use CSS `grid-template-rows: 0fr` → `1fr` transition (avoids max-height hacks)
  - Duration: 0.15s ease-out
  - Inner container: `overflow: hidden` during transition, `visible` after
- ToolCallBlock entry animation:
  - New blocks fade in: opacity 0 → 1, translateY(4px) → 0, 0.15s
  - Use `@starting-style` if browser support allows, otherwise class-based
- Status transitions (running → completed):
  - Spinner fades out, duration badge fades in, 0.1s
  - Left border color transitions smoothly
- Auto-scroll behavior:
  - Only auto-scroll if user is already at the bottom (within 100px)
  - If user has scrolled up to read, don't auto-scroll (respect their position)
  - "New activity below ↓" badge appears when new content arrives while scrolled up

**Verify**:
- [ ] Expand/collapse is smooth with no content jump
- [ ] New tool calls animate in subtly
- [ ] Status transition doesn't cause flash
- [ ] Auto-scroll respects user position
- [ ] "New activity" badge appears when scrolled up

### Slice 19.10.3: Keyboard Navigation

**Do this**:
- Create `useKeyboardNav` hook for tool call navigation
- When focus is in the chat view or agents view:
  - `j` / `↓` — focus next tool call block
  - `k` / `↑` — focus previous tool call block
  - `Enter` / `→` — expand focused block
  - `Esc` / `←` — collapse focused block
  - `c` — collapse all blocks
  - `e` — expand all blocks
- Focused block: subtle outline (`--color-accent`, 1px, 2px offset)
- Navigation wraps around (last → first, first → last)
- Only active when no text input is focused
- Show keyboard shortcut hints in a tooltip on the first visit (dismissible)

**Verify**:
- [ ] `j`/`k` navigate between tool call blocks
- [ ] `Enter`/`Esc` expand/collapse
- [ ] `c`/`e` collapse/expand all
- [ ] Focus outline visible
- [ ] Doesn't interfere with text input (chat box, search)
- [ ] Works in both chat and agents views

### Slice 19.10.4: Edge Cases & Error Recovery

**Do this**:
- Handle WebSocket disconnection:
  - Show subtle banner: "Connection lost — reconnecting..." in `--color-status-warning`
  - Tool calls in "running" state → show "Connection lost" instead of spinner
  - On reconnect, re-subscribe and resume (running calls may have completed — show "Status unknown")
- Handle missing tool events:
  - `tool_call_completed` without matching `tool_call_started` → create a synthetic entry
  - `tool_call_started` that never completes (>5 minutes) → show "Possibly stalled" warning
- Handle malformed output:
  - Unknown `output_type` → fall back to JSON pretty-print
  - Empty output → show "No output" message
  - Extremely large output (>100KB) → show "Output too large" with option to download
- Handle rapid page navigation:
  - Navigating away from chat during streaming → tool calls preserved in store
  - Navigating back → tool calls still visible under the correct message

**Verify**:
- [ ] WS disconnect shows warning, reconnect recovers
- [ ] Orphaned started events show stall warning after 5 minutes
- [ ] Unknown output type renders as JSON
- [ ] Large output shows download option
- [ ] Navigating away and back preserves state
