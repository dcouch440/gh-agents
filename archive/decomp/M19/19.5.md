# Ticket 19.5: Output Renderer Components

> Specialized components for rendering each type of tool output — syntax-highlighted code, diff views, file lists, search results, and terminal output.

## Goal

Each `ToolCallOutput` type gets a purpose-built renderer that displays data in the most useful format. File content is syntax-highlighted. Diffs show red/green inline changes. Search results show matched lines with context. File lists are compact and scannable. Terminal output is monospace with ANSI color support.

**Checkpoint**: A `Read` of a `.tsx` file shows syntax-highlighted JSX. An `Edit` shows the replaced lines in red/green diff format. A `Grep` for `"AuthService"` shows matched files with line numbers and highlighted match text. A `Bash` command shows stdout in a terminal-style block.

---

## Context

These plug into `ToolCallBlock` (19.4) via output delegation. Each renderer receives typed output data and renders it within the collapsible body section.

The existing `CodeBlock` component (prism-react-renderer with nightOwl theme) should be reused or extended for syntax highlighting.

**Key files**:

## Slices

### Slice 19.5.1: TextOutput — File Content & Plain Text

**Do this**:
- Create `TextOutput` component: `({ content: string, language?: string })`
- If `language` is provided (inferred from file extension by the parent):
  - Use `prism-react-renderer` with `nightOwl` theme (same as existing `CodeBlock`)
  - Show line numbers (right-aligned, `--color-text-tertiary`, non-selectable)
  - Max height 400px with overflow-y scroll
- If no language (plain text):
  - Render in monospace `<pre>` with `--color-text-primary`
  - Preserve whitespace
  - Max height 400px with scroll
- Add a copy button in the top-right corner (reuse pattern from `CodeBlock`)
- Add a line count label: `"{n} lines"` in tertiary text at the bottom-right

**Verify**:
- [ ] `.rs` file → Rust syntax highlighting
- [ ] `.tsx` file → TypeScript/JSX highlighting
- [ ] Unknown extension → plain monospace
- [ ] Copy button works
- [ ] Long files scroll, don't blow up layout
- [ ] Line numbers visible and non-selectable

---

### Slice 19.5.2: DiffOutput — Before/After Changes

**Do this**:
- Create `DiffOutput` component: `({ path: string, oldContent: string, newContent: string, replacements: number })`
- Compute line-level diff using a lightweight diff library (add `diff` package to `package.json`, or use a simple line-diff algorithm)
- Render inline diff (single column, not side-by-side):
  - Removed lines: `--color-status-error` text, `rgba(var(--status-error-rgb), 0.1)` background, `-` prefix
  - Added lines: `--color-status-success` text, `rgba(var(--status-success-rgb), 0.1)` background, `+` prefix
  - Context lines: `--color-text-secondary`, space prefix
  - Show 3 lines of context around each change, collapse unchanged middle sections with `"... {n} unchanged lines ..."`
- Header: file path in monospace, replacements count badge
- Max height 400px with scroll
- If `oldContent` is empty (new file), show all lines as added
- If `newContent` is empty (deleted file), show all lines as removed

**Verify**:
- [ ] Single-line edit → shows removed line (red) and added line (green) with context
- [ ] Multi-line edit → changed sections visible with collapsed unchanged sections
- [ ] New file (empty old) → all green
- [ ] Large diff → scrollable, collapsed middle sections
- [ ] File path shown in header

### Slice 19.5.3: FileListOutput — Glob Results

**Do this**:
- Create `FileListOutput` component: `({ files: string[] })`
- Render as a compact list:
  - Each file on its own line
  - Monospace font, 0.8125rem
  - File icon (lucide `File`) in `--color-text-tertiary`
  - Directory portions in `--color-text-secondary`, filename in `--color-text-primary`
    - e.g., `src/agents/` in gray, `executor.rs` in white
  - Group by directory if >10 files: show directory headers with count
- Count badge at the top: `"{n} files"` or `"{shown} of {total} files"` if truncated
- Max height 300px with scroll
- If empty: show `"No files found"` in tertiary text

**Verify**:
- [ ] 5 files → flat list, each with icon and highlighted filename
- [ ] 50 files → grouped by directory
- [ ] 0 files → empty state message
- [ ] Truncated results → shows count note
- [ ] Long paths don't break layout

### Slice 19.5.4: SearchMatchesOutput — Grep Results

**Do this**:
- Create `SearchMatchesOutput` component: `({ matches: SearchMatch[] })`
- Group matches by file
- For each file:
  - File path header (monospace, `--color-text-primary`, with file icon)
  - Match count badge: `"({n})"` in tertiary
  - Each match:
    - Line number in `--color-text-tertiary`, right-aligned, fixed width
    - Line content in monospace with the matched text highlighted (use `--color-accent` background, `--color-text-primary` text)
    - Context lines (before/after) in `--color-text-tertiary`, slightly indented
- Collapsible per-file sections if >3 files (first 3 files expanded, rest collapsed)
- Total match count at the top: `"{n} matches across {m} files"`
- Max height 400px with scroll

**Verify**:
- [ ] Matches grouped by file with file headers
- [ ] Matched text highlighted within lines
- [ ] Context lines shown when available
- [ ] >3 files → later files collapsed
- [ ] Match count accurate

### Slice 19.5.5: TerminalOutput — Bash & Test Output

**Do this**:
- Create `TerminalOutput` component: `({ content: string })`
- Render in a terminal-style block:
  - Black background (`--color-bg-primary`)
  - Monospace font, 0.8125rem
  - Border: 1px solid `--color-border`
  - Top bar: `"Terminal"` label in `--color-text-tertiary`, copy button
  - Preserve whitespace, wrap long lines
- Basic ANSI color support (optional, stretch goal):
  - Parse common ANSI escape codes (red, green, yellow, bold)
  - Use a lightweight library like `ansi-to-html` or manual regex
  - If too complex, strip ANSI codes and render plain
- Max height 400px with scroll
- Auto-scroll to bottom when content updates (for running commands)

**Verify**:
- [ ] Bash output renders in terminal style
- [ ] Long output scrolls
- [ ] Copy button copies raw text (without ANSI codes)
- [ ] Whitespace preserved (indentation, blank lines)
