# Ticket 19.8: Chat Integration & Streaming

> Tool execution blocks appear inline in the chat conversation, nested under the agent's response — the primary place users watch agents work.

## Goal

When a user sends a message that triggers agent execution, the chat view shows tool calls appearing in real time within the conversation. Tool blocks are interleaved with the agent's text response, just like Claude Code shows tool calls between text blocks. The user watches the agent think, call tools, get results, and synthesize — all in the chat flow.

**Checkpoint**: User sends "find all auth files and summarize them". Chat shows: assistant message starts streaming → `[Glob] **/*auth*` block appears with expanding file list → `[Read] src/github/auth.rs` block appears with code → more text streams in → final summary appears. All inline, no page navigation needed.

---

## Context

Currently, chat messages are rendered as flat text (user) or markdown (assistant) via the `Message` component. This ticket embeds `ToolCallBlock` components within the assistant message flow, creating a rich, structured conversation view.

**Key files**:
- `ui/src/components/Message/Message.tsx` — Extend to render tool call blocks
- `ui/src/pages/ChatPage/ChatPage.tsx` — Wire agent activity into chat
- `ui/src/hooks/useChat.ts` — Extend to associate tool calls with messages
- New `ui/src/components/AgentMessage/AgentMessage.tsx` — Rich agent response with embedded tool calls

**Dependencies**: 19.4, 19.5

## Slices

### Slice 19.8.1: AgentMessage Component

**Do this**:
- Create `AgentMessage` component: `({ message, toolCalls, isStreaming })`
- Renders an agent response as a sequence of interleaved blocks:
  - Text blocks: rendered via existing `MarkdownContent`
  - Tool call blocks: rendered via `ToolCallBlock` (from 19.4)
  - The sequence preserves the order: text → tool call → tool call → text → tool call → text
- Ordering: tool calls are placed based on their `startedAt` timestamp relative to the text streaming position
  - If we can't precisely interleave (text comes as one block), show tool calls before the final text
  - Layout: tool calls indented slightly (left margin 1rem) to distinguish from main text
- Agent type badge at the top of the message (if from a subagent, not the main orchestrator)
- Subagent messages grouped under a collapsible section:
  - Header: `"▸ explorer subagent — 5 tool calls, 2.3s"`
  - Click to expand/collapse the subagent's tool call sequence

**Verify**:
- [ ] Tool calls appear between text blocks in correct order
- [ ] Tool calls visually distinct from prose (indented, styled differently)
- [ ] Subagent work is grouped and collapsible
- [ ] Streaming text + live tool calls render without flicker
- [ ] Existing plain-text messages still render normally

### Slice 19.8.2: Chat-Tool Call Association

**Do this**:
- Extend `useChat` hook to associate tool calls with chat messages:
  - When agent activity is happening in response to a user message, link the tool calls to that message's response
  - Use the `task_id` from tool events to match against the chat message that triggered the task
  - New state: `messageToolCalls: Map<string, ToolCall[]>` — message_id → tool calls
- When a new chat message response starts:
  - Start collecting tool events for the active task
  - Associate them with the response message
- When the response completes:
  - Finalize the tool call list for that message

**Verify**:
- [ ] Tool calls linked to the correct response message
- [ ] Multiple sequential messages each get their own tool calls
- [ ] Tool calls from unrelated agents don't leak into chat messages
- [ ] Scrolling back to old messages shows their associated (completed) tool calls

---

### Slice 19.8.3: Streaming Integration

**Do this**:
- During active streaming (SSE `chat_stream` endpoint), integrate tool call display:
  - Text tokens stream into the `MarkdownContent` as before
  - Tool call events from WS interleave: when a `tool_call_started` arrives during streaming, insert a `ToolCallBlock` at the current position
  - The block starts in "running" state with spinner
  - When `tool_call_completed` arrives, block transitions to completed state
  - More text may stream after tool calls
- Handle the visual transition smoothly:
  - Tool call blocks should push text below them (not overlay)
  - Auto-scroll to keep the latest content visible
  - No layout shift when a tool call transitions from running to completed

**Verify**:
- [ ] Text streams in, tool call block appears mid-stream, more text follows
- [ ] Running tool call shows spinner within the chat flow
- [ ] Completed tool call collapses smoothly
- [ ] Auto-scroll follows the latest content
- [ ] No layout shift on tool call completion

---

### Slice 19.8.4: Orchestrator Delegation Display

**Do this**:
- When the orchestrator spawns subagents (M18), show delegation in the chat:
  - "Delegating to 3 subagents..." message with agent type badges
  - Each subagent gets a collapsible section:
    - Header: `"▸ explorer — finding auth files"` with status dot
    - Body: that subagent's `ToolCallBlock` timeline
  - When all subagents complete, show the synthesized final response
- Delegation sections are collapsible (collapsed by default after completion)
- Active subagents are expanded by default
- Visual hierarchy:
  - User message
  - Orchestrator text: "I'll analyze this in three parts..."
  - `├── explorer subagent` (expanded, showing tool calls)
  - `├── coder subagent` (expanded, showing tool calls)
  - `└── tester subagent` (collapsed, completed)
  - Orchestrator synthesis: "Based on the analysis..."

**Verify**:
- [ ] Delegation clearly shows parent → child relationship
- [ ] Each subagent's tool calls visible in its section
- [ ] Active subagents expanded, completed ones collapsed
- [ ] Final synthesis appears after all subagents complete
- [ ] Entire delegation section collapsible for completed conversations
