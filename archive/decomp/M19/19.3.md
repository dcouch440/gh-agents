# Ticket 19.3: Agent Activity Store & Hook

> Zustand store and React hook that manage agent tool execution state — the data layer between WebSocket events and UI components.

## Goal

A `useAgentActivity` hook provides live tool execution data for any agent. Components call it with an agent ID and get back a list of tool calls (in progress + completed), subscription status, and controls. A Zustand store accumulates events and manages lifecycle.

**Checkpoint**: `const { toolCalls, isActive } = useAgentActivity(agentId)` — `toolCalls` updates in real time as tool events arrive, each entry has `status: "running" | "completed" | "failed"`, output data, and duration.

---

## Context

The UI currently has no concept of tool execution. `useFeed` handles flat text events. This ticket creates the state management for structured tool call data that the rendering components (19.4, 19.5) will consume.

**Key files**:
- New `ui/src/store/agentActivity.ts` — Zustand store

- `ui/src/api/websocket.ts` — Register handler for tool events

### Slice 19.3.1: TypeScript Types

**Do this**:
- Create `ui/src/api/types/toolEvents.ts`
- Define types matching the WS protocol:
```typescript
interface ToolCallStarted {
  tool_call_id: string;
  agent_id: string;
  agent_type_id?: string;
  task_id?: string;
  tool_name: string;
  tool_args: Record<string, unknown>;
  timestamp: string;
}

interface ToolCallCompleted {
  tool_call_id: string;
  agent_id: string;
  tool_name: string;
  success: boolean;
  output: unknown;
  output_type: 'text' | 'file_list' | 'search_matches' | 'diff' | 'empty';
  error?: string;
  duration_ms: number;
  truncated: boolean;
  timestamp: string;
}

// Unified view for components:
interface ToolCall {
  id: string;
  agentId: string;
  agentTypeId?: string;
  toolName: string;
  args: Record<string, unknown>;
  status: 'running' | 'completed' | 'failed';
  output?: ToolCallOutput;
  error?: string;
  durationMs?: number;
  truncated: boolean;
  startedAt: string;
  completedAt?: string;
}

type ToolCallOutput =
  | { type: 'text'; content: string }
  | { type: 'file_list'; files: string[] }
  | { type: 'search_matches'; matches: SearchMatch[] }
  | { type: 'diff'; path: string; oldContent: string; newContent: string; replacements: number }
  | { type: 'empty' };

interface SearchMatch {
  file: string;
  lineNumber: number;
  lineContent: string;
  contextBefore: string[];
  contextAfter: string[];
}
```

**Verify**:
- [ ] Types compile without errors
- [ ] `ToolCall` union status covers all states
- [ ] `ToolCallOutput` discriminated union covers all output types

### Slice 19.3.2: Zustand Store

**Do this**:
- Create `ui/src/store/agentActivity.ts`
- Define `AgentActivityStore`:
  - `toolCalls: Map<string, ToolCall>` — keyed by tool_call_id
  - `byAgent: Map<string, string[]>` — agent_id → list of tool_call_ids (ordered)
  - `activeAgents: Set<string>` — agents with at least one running tool call
- Actions:
  - `handleToolCallStarted(event: ToolCallStarted)` — create `ToolCall` with status `"running"`, add to maps
  - `handleToolCallCompleted(event: ToolCallCompleted)` — update status to `"completed"` or `"failed"`, fill in output/duration
  - `getToolCallsForAgent(agentId: string): ToolCall[]` — returns ordered list
  - `clearAgent(agentId: string)` — remove all tool calls for an agent (cleanup)
  - `clearAll()` — reset store
- Cap at 500 tool calls total (evict oldest completed when exceeded)

**Verify**:
- [ ] `handleToolCallStarted` creates entry with `status: "running"`
- [ ] `handleToolCallCompleted` updates matching entry to `"completed"` or `"failed"`
- [ ] `getToolCallsForAgent` returns calls in chronological order
- [ ] Cap enforced: 501st call evicts oldest completed call
- [ ] `clearAgent` removes all calls for that agent

### Slice 19.3.4: useAgentActivity Hook

**Do this**:
- Create `ui/src/hooks/useAgentActivity.ts`
- Hook signature: `useAgentActivity(agentId?: string): AgentActivityResult`
- `AgentActivityResult`:
  - `toolCalls: ToolCall[]` — all tool calls for this agent (or all agents if no ID), ordered chronologically
  - `runningCalls: ToolCall[]` — subset with `status === "running"`
  - `isActive: boolean` — true if any calls are running
  - `totalCalls: number`
  - `totalDurationMs: number` — sum of all completed call durations
- On mount: subscribe to `tool_events` channel (with agent_id filter if provided)
- On unmount: unsubscribe
- Use `useSyncExternalStore` or Zustand selector for reactive updates

**Verify**:
- [ ] Hook subscribes to WS on mount, unsubscribes on unmount
- [ ] `toolCalls` updates when new events arrive
- [ ] `isActive` is true when any call is running, false when all completed
- [ ] `totalDurationMs` sums completed call durations
- [ ] Calling without `agentId` returns all tool calls across agents
