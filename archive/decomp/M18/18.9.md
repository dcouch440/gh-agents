# Ticket 18.9: Agent Toolkit & Tool Execution Loop

> Wire the execution layer into the agent runtime so subagents can actually use tools — not just call the LLM and return text.

## Goal

Agents get an `AgentToolkit` that dispatches tool calls based on their `ToolPermission` set. The LLM is prompted with available tools (Anthropic tool_use format), and when it returns tool calls, the executor runs them against the real execution layer. Agents loop: call LLM → execute tool → feed result back → call LLM again, until the LLM returns a final text response.

**Checkpoint**: An `explorer` agent spawned with task "find all files that import AuthService" actually reads the filesystem via `FileOps`, searches file contents via `Grep`, and returns real results — not hallucinated guesses.

---

## Context

The execution layer (`src/execution/`) is fully built (M7) and extended (18.8) but completely disconnected from agents. Right now agents call the LLM once and return whatever text it produces. They can't actually touch the codebase.

**Key files**:
- New `src/agents/toolkit.rs` — Tool registry, dispatch, permission enforcement
- `src/agents/executor.rs` — Multi-turn tool-use loop
- `src/agents/mod.rs` — Module export
- `src/llm/anthropic.rs` — Tool-use request/response support

**Dependencies**: 18.1 (for `ToolPermission`), 18.8 (for Glob, Grep, Edit)

### Slice 18.9.2: AgentToolkit — Permission-Gated Dispatch

**Do this**:
- Add `AgentToolkit` struct holding:
  - `file_ops: FileOps`
  - `git_ops: GitOps`
  - `sandbox: Sandbox`
  - `test_runner: TestRunner`
  - `search: SearchOps` (Glob + Grep from 18.8)
  - `edit_ops: EditOps` (from 18.8)
  - `permissions: Vec<ToolPermission>`
- Implement `execute(tool: AgentTool) -> Result<ToolResult, ToolError>`:
  - Check if the tool is allowed by `permissions`:
    - `Read`, `Glob`, `Grep` → require `FileRead`
    - `Write`, `Edit` → require `FileWrite`
    - `Bash` → require `ShellExec`
    - `GitStatus`, `GitDiff`, `GitCommit` → require `GitOps`
    - `RunTests` → require `ShellExec`
  - If denied → return `ToolError::PermissionDenied`
  - If allowed → dispatch to the appropriate execution layer, return `ToolResult`
- Implement `available_tools(&self) -> Vec<ToolDefinition>`:
  - Returns only the tools this agent is permitted to use
  - `ToolDefinition` matches Anthropic's tool schema format (name, description, input_schema)

**Verify**:
- [ ] Explorer (FileRead + LlmCall) → can Read, Glob, Grep; denied Write, Bash, Git
- [ ] Coder (FileRead + FileWrite + LlmCall) → can Read, Write, Edit, Glob, Grep; denied Bash, Git
- [ ] Tester (FileRead + ShellExec + LlmCall) → can Read, Glob, Grep, Bash, RunTests; denied Write, Git
- [ ] `available_tools()` returns correct subset for each permission set
- [ ] Permission denied returns clear error message

### Slice 18.9.4: Multi-Turn Tool Execution Loop

**Do this**:
- Replace the single-shot `execute_task` flow with an agentic loop:
  1. Call LLM with system prompt + task + available tools
  2. If response has `stop_reason: "tool_use"`:
     a. Parse tool call(s) from response content blocks
     b. Execute each tool via `AgentToolkit::execute()`
     c. Build `tool_result` content blocks with outputs
     d. Append assistant message + tool results to conversation
     e. Call LLM again (go to step 2)
  3. If response has `stop_reason: "end_turn"`:
     a. Extract final text response
     b. Return as `TaskResult`
- Add max iterations guard (e.g., 25 tool calls) to prevent infinite loops
- Send `ProgressUpdate` after each tool execution

**Verify**:
- [ ] Agent calls LLM → gets tool_use → executes tool → feeds result back → gets final answer
- [ ] Multi-step: agent reads file, then edits it, then reads again to verify
- [ ] Max iterations prevents infinite loop
- [ ] Progress updates sent during tool execution
- [ ] Agents without toolkit still work (single LLM call, no tools)
- [ ] Timeout still enforced across the full loop
