# Ticket 18.6: Manual Spawn API

> Users spawn agents via REST and chat commands.

## Goal

Users can manually spawn typed subagents via `POST /api/agents/spawn`, list available types via `GET /api/agent-types`, check ephemeral agent status, receive WebSocket events, and use a `/spawn` chat command.

**Checkpoint**: `POST /api/agents/spawn {"agent_type_id": "explorer", "task_description": "find auth files"}` returns 201 with agent_id. WebSocket subscribers on `"agents"` channel receive `subagent_spawned` event.

---

## Context

This gives users direct control over subagent spawning, complementing the automatic orchestrator-driven spawning in 18.4.

**Key files**:
- `src/server/api.rs` — New endpoints
- `src/server/ws.rs` — New WebSocket event types
- `src/server/mod.rs` — Route registration
- `src/server/state.rs` — May need pool/dispatcher access

**Dependencies**: 18.1

## Slices

### Slice 18.6.1: POST /api/agents/spawn

**Do this**:
- Add `SpawnAgentRequest` struct:
  - `agent_type_id: String`
  - `task_description: String`
  - `tier_override: Option<String>` (optional tier override)
- Add `SpawnAgentResponse` struct:
  - `agent_id: String`
  - `agent_type_id: String`
  - `status: String` (always `"spawned"`)
- Implement `spawn_agent` handler:
  - Validate `agent_type_id` exists in registry → 400 if not found
  - Validate `task_description` is not empty → 400
  - Build a `TaskAssignment` from the description
  - Create a `SpawnRequest` and call the spawner
  - Return 201 with agent_id

**Verify**:
- [ ] Valid request → 201 with `agent_id`
- [ ] Unknown agent type → 400
- [ ] Empty task description → 400
- [ ] Request/response serialize correctly

### Slice 18.6.4: WebSocket Events

**Do this**:
- Add new `ServerMessage` variants to `ws.rs`:
  - `SubagentSpawned { data: SubagentEvent }` with `serde(rename = "subagent_spawned")`

- Add `SubagentEvent` struct:
  - `agent_id: String`
  - `agent_type_id: String`
  - `parent_agent_id: Option<String>`
  - `task_id: Uuid`
  - `timestamp: DateTime<Utc>`
- Broadcast events when subagents are spawned/completed (via `state.agent_tx`)

**Verify**:
- [ ] `subagent_spawned` event serializes correctly
- [ ] `subagent_completed` event serializes correctly
- [ ] Events are broadcast to WebSocket subscribers on `"agents"` channel

### Slice 18.6.5: Chat Command /spawn

**Do this**:
- In the chat message handler (`send_chat` in `api.rs`), detect `/spawn` command:
  - Parse format: `/spawn <agent_type> "<task description>"`
  - Example: `/spawn explorer "find all auth-related files"`
  - Validate agent type exists
  - Create spawn request and execute
  - Return message ID (same as normal chat)
- Invalid format → return 400 with helpful error message

**Verify**:
- [ ] `/spawn explorer "find auth files"` → spawns explorer agent
- [ ] `/spawn unknown_type "task"` → 400 with "unknown agent type"
- [ ] `/spawn` with no args → 400 with usage hint
- [ ] Regular chat messages still work as before
