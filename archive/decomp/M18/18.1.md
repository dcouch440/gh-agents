# Ticket 18.1: AgentType Registry

> Define `AgentType` as the specialization unit — binds a role to spawn config, tool permissions, and tier defaults.

## Goal

A new `AgentTypeRegistry` holds typed agent definitions. Five built-in types are registered at startup. The registry is accessible from `AppState`.

**Checkpoint**: `AgentTypeRegistry::with_builtins()` returns a registry with 5 types. Each type has correct permissions and tier. Registry rejects duplicates.

---

## Context

This is the foundation for the entire typed subagent system. Every other ticket depends on `AgentType` and the registry.

**Key files**:
- New `src/agents/agent_type.rs` — All types and registry
- `src/agents/mod.rs` — Add module declaration and exports
- `src/server/state.rs` — Wire registry into `AppState`

**Dependencies**: None

### Slice 18.1.4: Built-in Types

**Do this**:
- Add `builtin_types() -> Vec<AgentType>` function that returns 5 types:
  - `explorer`: Utility tier, FileRead + LlmCall, max_concurrent=4, timeout=120s
  - `coder`: Worker tier, FileRead + FileWrite + LlmCall, max_concurrent=3, timeout=300s
  - `tester`: Worker tier, FileRead + ShellExec + LlmCall, max_concurrent=2, timeout=300s
  - `reviewer`: Worker tier, FileRead + LlmCall, max_concurrent=2, timeout=180s
  - `planner`: Orchestrator tier, LlmCall only, max_concurrent=1, timeout=180s
- Each type's `role_id` maps to existing roles: `"utility"`, `"worker"`, `"orchestrator"`

**Verify**:
- [ ] `builtin_types()` returns exactly 5 types
- [ ] Explorer: Utility tier, read-only + LLM, no write/shell/git
- [ ] Coder: Worker tier, has FileRead + FileWrite + LlmCall
- [ ] Tester: Worker tier, has FileRead + ShellExec + LlmCall
- [ ] Reviewer: Worker tier, has FileRead + LlmCall, no FileWrite
- [ ] Planner: Orchestrator tier, LlmCall only
