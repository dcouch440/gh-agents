# Ticket 18.8: Search & Edit Operations

> Add Glob, Grep, and string-replacement Edit to the execution layer — the missing tools agents need before they can work like Claude Code.

## Goal

Three new execution-layer capabilities: glob-based file search, regex content search, and string-replacement file editing. These fill the gaps between what Claude Code can do and what our execution layer currently provides.

**Checkpoint**: `Glob::find("**/*.rs", root)` returns all Rust files. `Grep::search("fn main", root, defaults)` finds main functions with line numbers. `EditOps::replace(path, "old", "new", false)` performs a single unique replacement.

---

## Context

The execution layer (`src/execution/`) has `FileOps` (read/write), `GitOps`, `Sandbox`, and `TestRunner` — but no file search or string-replacement editing. Agents need these to navigate and modify codebases the way Claude Code does.

| Claude Code Tool | Our Execution Layer | Status |
|---|---|---|
| Glob | — | **Missing** |
| Grep | — | **Missing** |
| Edit | — | **Missing** |

**Key files**:
- New `src/execution/search.rs` — Glob and Grep implementations
- New `src/execution/edit.rs` — String-replacement file editing
- `src/execution/mod.rs` — New module exports

**Dependencies**: None (pure execution-layer additions)

## Slices

### Slice 18.8.1: Glob — File Pattern Search

**Do this**:
- Add `search.rs` to `src/execution/`
- Implement `Glob` struct with method:
  - `find(pattern: &str, base_dir: &Path) -> Result<Vec<PathBuf>, SearchError>`
  - Use the `glob` crate (add to `Cargo.toml`)
  - Scope results to `ExecutionContext` project root
  - Sort results by path
  - Limit to 1000 results
- Add `SearchError` enum

**Verify**:
- [ ] `Glob::find("**/*.rs", project_root)` returns all Rust files
- [ ] `Glob::find("src/agents/*.rs", root)` returns only agent module files
- [ ] Results are scoped to project root (no escaping)
- [ ] Over 1000 matches → truncated with warning

---

### Slice 18.8.2: Grep — Content Search

**Do this**:
- Add to `search.rs`:
  - `Grep::search(pattern: &str, path: &Path, options: GrepOptions) -> Result<Vec<GrepMatch>, SearchError>`
  - `GrepOptions`: `case_insensitive: bool`, `max_results: usize`, `include_glob: Option<String>`, `context_lines: usize`
  - `GrepMatch`: `file: PathBuf`, `line_number: usize`, `line_content: String`, `context_before: Vec<String>`, `context_after: Vec<String>`
- Use regex crate for pattern matching
- Walk directory tree, skip binary files, respect `.gitignore` if possible
- Scope to `ExecutionContext` project root

**Verify**:
- [ ] `Grep::search("fn main", root, defaults)` finds main functions
- [ ] Case-insensitive search works
- [ ] Context lines included when requested
- [ ] Binary files skipped
- [ ] Results limited to `max_results`

---

### Slice 18.8.3: Edit — String-Replacement File Editing

**Do this**:
- Add `edit.rs` to `src/execution/`
- Implement `EditOps` struct with:
  - `replace(path: &Path, old: &str, new: &str, replace_all: bool) -> Result<EditResult, EditError>`
  - Reads file, finds `old` string, replaces with `new`, writes back
  - If `replace_all` is false, `old` must be unique in the file (error if multiple matches)
  - `EditResult`: `path: PathBuf`, `replacements: usize`
- Use `ExecutionContext` for path validation
- `EditError` variants: `NotFound`, `PathOutsideProject`, `MultipleMatches`, `NoMatch`, `IoError`

**Verify**:
- [ ] Single unique match → replaced successfully
- [ ] `replace_all: true` → all occurrences replaced
- [ ] `replace_all: false` with multiple matches → `MultipleMatches` error
- [ ] No matches → `NoMatch` error
- [ ] Path outside project → rejected
