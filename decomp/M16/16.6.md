# Ticket 16.6: Encrypted Secrets Storage

> Per-tenant encrypted storage for API keys and tokens. Never stored in plaintext.

## Goal

Each org's sensitive data (Anthropic API keys, GitHub access tokens) is encrypted at rest. Decryption only happens at runtime when the secret is needed. API never returns raw secret values.

**Checkpoint**: Org stores an Anthropic API key, it's encrypted in DB, agents use it to make LLM calls, API returns masked value only.

---

## Context

Currently API keys are in config files on disk. SaaS mode needs per-org secrets that are encrypted in Postgres and decryptable at runtime using a server master key.

**Key files**:
- `src/server/api.rs` — Secret management endpoints
- `src/db/mod.rs` — Encrypted storage queries
- `src/llm/` — Reads API key at call time
- `src/github/` — Reads GitHub token at call time

**Dependencies**:
- Requires 16.1 (Postgres) and 16.2 (Org model) complete

## Slices

### Slice 16.6.1: Encryption Module

**Do this**:
- Add `aes-gcm` crate to Cargo.toml
- Create `src/secrets/mod.rs`:
  - `encrypt(plaintext: &str, master_key: &[u8]) -> EncryptedBlob`
  - `decrypt(blob: &EncryptedBlob, master_key: &[u8]) -> String`
  - AES-256-GCM with random nonce per encryption
  - `EncryptedBlob` = nonce + ciphertext, stored as base64 in DB
- Master key loaded from `NEXOR_MASTER_KEY` env var (32 bytes, base64-encoded)
- Fail startup if master key is missing or invalid length

- `src/secrets/mod.rs` (new)
- `src/config/mod.rs`

### Slice 16.6.2: Secrets Table & CRUD

**Do this**:
- Create `org_secrets` table: `org_id` (FK), `key_name` (TEXT, e.g. "anthropic_api_key", "github_token"), `encrypted_value` (TEXT), `updated_at`
  - Composite PK: `(org_id, key_name)`
- DB functions:
  - `set_secret(org_id, key_name, plaintext)` → encrypts and upserts
  - `get_secret(org_id, key_name)` → decrypts and returns plaintext
  - `delete_secret(org_id, key_name)`
  - `list_secret_keys(org_id)` → returns key_names only (no values)

**Create/modify**:
- `migrations/` — org_secrets table
- `src/db/mod.rs`
- `src/secrets/mod.rs`

### Slice 16.6.3: Secrets API Endpoints

**Do this**:
- `GET /api/orgs/:id/secrets` — List secret key names with masked previews (e.g., `sk-...7f3a`)
  - Never return full values
- `PUT /api/orgs/:id/secrets/:key_name` — Set/update secret (admin/owner only)
  - Body: `{ value: "sk-ant-..." }`
  - Encrypts and stores
- `DELETE /api/orgs/:id/secrets/:key_name` — Delete secret (admin/owner only)
- `POST /api/orgs/:id/secrets/:key_name/verify` — Test the secret works
  - For Anthropic: make a test API call
  - For GitHub: verify token with `GET /user`

## Notes

- Master key rotation: future enhancement. Would require re-encrypting all secrets with new key.
- Consider using a secrets manager (AWS KMS, HashiCorp Vault) in production. This implementation is the self-hosted baseline.
- GitHub OAuth tokens from 16.3 are stored here per-user within the org, not just per-org. Key name format: `github_token:{user_id}`.
