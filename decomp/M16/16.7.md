# Ticket 16.7: Collaborative Chat Rooms

> Shared async chat rooms where team members and AI all participate. The AI listens, contributes, and updates the team.

## Goal

Multiple users in an org share chat rooms. Everyone sees the same messages in real-time. The AI is a participant — it listens to the conversation, responds when addressed, and proactively shares updates about agent work. Like a team Slack channel where the AI is a helpful teammate.

**Checkpoint**: Two users in the same org are in a chat room. User A says something. User B sees it instantly. The AI chimes in with a relevant observation. Agent finishes a task and posts an update to the room.

---

## Context

Current chat is single-user to orchestrator. This ticket transforms it into a multi-user room model where the AI is one participant among many.

**Key files**:
- `src/server/api.rs` — Chat API endpoints (rewrite from 1:1 to rooms)
- `src/server/ws.rs` — WebSocket broadcast (update for room-scoped messages)
- `src/db/mod.rs` — Chat room and message storage
- `ui/src/pages/` — Chat UI (update)

**Dependencies**:
- Requires 16.1 (Postgres), 16.2 (Users/Orgs), 16.5 (Tenant isolation)

### Slice 16.7.2: Chat Room API

**Do this**:
- `POST /api/chat/rooms` — Create room (name, type, repo_id optional)
- `GET /api/chat/rooms` — List rooms for current org (with unread counts)
- `GET /api/chat/rooms/:id` — Get room details with member list
- `POST /api/chat/rooms/:id/join` — Join room
- `POST /api/chat/rooms/:id/leave` — Leave room
- `POST /api/chat/rooms/:id/messages` — Send message (body: `{ content, reply_to? }`)
- `GET /api/chat/rooms/:id/messages` — Get messages (paginated, cursor-based for infinite scroll)
  - Returns: sender name, avatar, content, timestamp, reply chain
- `POST /api/chat/rooms/:id/read` — Mark room as read up to latest message

### Slice 16.7.4: AI Participant — Reactive Responses

**Do this**:
- AI monitors messages in rooms it's a member of
- **Direct address**: Messages containing `@nexor` or `@ai` trigger an immediate AI response
  - AI reads recent room context (last N messages) to form a relevant reply
  - Response streams in via SSE, final message saved to room
- **Question detection**: Messages ending with `?` that seem directed at the AI get a response
- AI sends messages with `sender_type: ai` and a display name ("nexor")
- Rate limit: max 1 AI response per 30 seconds per room (configurable)

### Slice 16.7.5: AI Participant — Proactive Updates

**Do this**:
- Agents post to relevant chat rooms when:
  - **Task started**: "Starting work on: {task_title}" → repo room
  - **Task completed**: "Finished: {task_title}. PR #{number} is ready for review." → repo room
  - **Task failed**: "Hit an issue with {task_title}: {error_summary}. Need help?" → repo room
  - **PR created**: "Created PR #{number}: {title}" → repo room
  - **Milestone completed**: "Milestone complete: {title}" → general room
- Messages are contextual, not spammy — one message per event, not per step
- Users can mute AI updates per room
- AI occasionally synthesizes: "Busy day — 4 PRs merged, 2 in review, 1 blocked on test failures."

### Slice 16.7.6: AI Participant — Conversational Awareness

**Do this**:
- AI reads ongoing conversations and contributes when it has relevant context:
  - User A: "I think we should refactor the auth module"
  - User B: "Yeah the token refresh is broken"
  - AI: "I can see the issue — `refresh_token()` in `src/auth/tokens.rs:47` doesn't handle expired refresh tokens. Want me to create a task for that?"
- AI builds context from: room history, repo files, recent task/PR activity
- Trigger: AI evaluates every N messages (configurable, default 5) whether it has something useful to add
- If nothing useful, stay silent — no filler responses
- Cooldown: at least 2 minutes between unsolicited AI messages

## Notes

- Chat rooms replace the current 1:1 chat model. The old `/api/chat` endpoints are deprecated.
- The AI's chat personality should be helpful but not overbearing. It's a teammate, not a bot.
- Message history is searchable (future enhancement: full-text search with Postgres `tsvector`).
- Direct messages (DMs) between two users are just a room with `type: direct` and two members.
- Consider end-to-end encryption for DMs in the future.
