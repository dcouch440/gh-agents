# Ticket 16.8: Presence & User Awareness

> Real-time presence system: who's online, what they're viewing, typing indicators.

## Goal

Users see who else is online in their org, what file or page they're viewing, and typing indicators in chat. Makes the app feel alive and collaborative.

**Checkpoint**: Two users online. Each sees the other's avatar with a green dot. Opening a file shows "Also viewing: User B". Typing in chat shows "User B is typing..."

---

## Context

Presence is built on the existing WebSocket infrastructure. Each connected client reports its state, the server aggregates and broadcasts.

**Key files**:
- `src/server/ws.rs` — WebSocket handler (add presence protocol)
- `src/server/api.rs` — Presence API
- `ui/src/` — Presence components throughout the UI

**Dependencies**:
- Requires 16.2 (Users), 16.7 (Chat rooms for typing indicators)

## Slices

### Slice 16.8.1: Presence Backend

**Do this**:
- Track connected users per org in server memory (not DB — ephemeral)
- Data per connection: `{ user_id, org_id, status: online/away/busy, current_view: string, connected_at }`
- On WebSocket connect: add to presence map, broadcast `user_online` to org
- On WebSocket disconnect: remove from presence map, broadcast `user_offline` to org
- `GET /api/presence` — List currently online users in org with their status and current view
- Heartbeat: clients send ping every 30 seconds, mark as `away` after 5 min idle, remove after 10 min no heartbeat

### Slice 16.8.2: View Tracking

**Do this**:
- Clients send `view_changed` WebSocket messages when navigating:
  - `{ type: "view_changed", view: "editor", file: "src/main.rs" }`
  - `{ type: "view_changed", view: "chat", room: "general" }`
  - `{ type: "view_changed", view: "tasks" }`
- Server updates presence map and broadcasts to org
- "Also viewing this file" indicator on editor and other pages
- Debounce: only send view change after 1 second of stability (not on every keystroke/scroll)

### Slice 16.8.3: Typing Indicators

**Do this**:
- Clients send `typing_start` when user begins typing in a chat room
- Clients send `typing_stop` when user stops typing (debounce 2 seconds after last keystroke)

- Auto-clear typing after 5 seconds with no update (in case client disconnects mid-type)

## Notes

- Presence is fully in-memory on the server — no DB writes. If the server restarts, all presence resets (acceptable for v1).
- Future enhancement: Redis-backed presence for horizontal scaling (multiple server instances).
- Cursor position sharing sends line/column, not character-by-character — lightweight.
- Privacy: users can set status to "busy" to hide their current view.
