# Ticket 16.3: GitHub OAuth & Account Connect

> Sign in with GitHub, connect GitHub account, browse repos, authorize nexor access.

## Goal

Users can sign up and log in with their GitHub account. After connecting, nexor can access their repos and orgs via the GitHub API. This is the front door of the product.

**Checkpoint**: Click "Sign in with GitHub" → authorize → land in the app with GitHub avatar and repos visible.

---

## Context

GitHub OAuth App flow: redirect to GitHub → user authorizes → callback with code → exchange for token → store token → use GitHub API.

**Key files**:
- `src/server/auth.rs` — Auth endpoints
- `src/github/` — Existing GitHub API client (has device flow, needs OAuth web flow)
- `src/server/api.rs` — API endpoints
- `ui/src/pages/` — Login, onboarding pages

**Dependencies**:
- Requires 16.1 (Postgres) and 16.2 (User model) complete
- Requires a registered GitHub OAuth App (client_id, client_secret)

## Slices

### Slice 16.3.1: GitHub OAuth Server Endpoints

**Do this**:
- Add GitHub OAuth config: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_CALLBACK_URL` (env vars)
- `GET /api/auth/github` — Redirect to GitHub authorization URL with scopes: `user:email`, `repo`, `read:org`
  - Generate and store a `state` param for CSRF protection
- `GET /api/auth/github/callback` — Handle callback
  - Exchange `code` for access token via `POST https://github.com/login/oauth/access_token`
  - Fetch user profile from `GET https://api.github.com/user`
  - Fetch user emails from `GET https://api.github.com/user/emails`
  - If user exists (match on `github_id`): log them in, return JWT
  - If new user: create account (email from GitHub, avatar_url, display_name from GitHub profile), create personal org, return JWT
- Store GitHub access token encrypted in secrets table (ticket 16.6)

**Create/modify**:
- `src/server/auth.rs`
- `src/config/mod.rs`

### Slice 16.3.2: GitHub Account Linking

**Do this**:
- `POST /api/auth/github/connect` — For existing email+password users who want to link GitHub
  - Same OAuth redirect flow but links to existing user instead of creating new
  - Stores `github_id` and access token on user record
- `DELETE /api/auth/github/disconnect` — Unlink GitHub (only if user has a password set)
- `GET /api/users/me/github` — Show GitHub connection status (connected/disconnected, GitHub username)

### Slice 16.3.3: GitHub Repo Browser API

**Do this**:
- `GET /api/github/repos` — List user's GitHub repos (personal + org repos they have access to)
  - Paginated, searchable by name
  - Returns: name, full_name, description, language, private/public, default_branch, updated_at
  - Uses the stored GitHub access token
- `GET /api/github/orgs` — List user's GitHub organizations
- `GET /api/github/repos/:owner/:repo` — Get single repo details
- Cache results for 5 minutes to avoid rate limiting

## Notes

- GitHub OAuth App must be registered at https://github.com/settings/developers
- Scopes: `user:email` (get email), `repo` (access repos), `read:org` (list org memberships)
- Access tokens should be refreshed — GitHub OAuth tokens don't expire by default, but GitHub Apps tokens do. Start with OAuth App, migrate to GitHub App later if needed.
- The callback URL must match exactly what's registered on GitHub
