# Ticket 6.2: Layout System

> Define fixed panel arrangement with header, main area, and input bar.

## Goal

Create a consistent layout system that divides the terminal into:
- **Header bar** (1 line): Shows agent status (`w[0/6] o[0/2]`) and current view
- **Main area** (flexible): Content area for views
- **Input bar** (1-2 lines): Text input and status messages

**Checkpoint**: TUI displays header with agent counts, main content area, and input bar at bottom.

---

## Context

The layout is FIXED - no resizing, no rearranging. This provides a predictable, consistent experience. All views render into the main content area while header and input bar remain constant.

**Key files**:
- `src/tui/layout.rs` - Layout constraints and helpers (create)
- `src/tui/app.rs` - Integrate layout into render loop (modify)

**Dependencies**:
- Requires 6.1 (Terminal Setup) complete

**References**:
- See `PRD.md` "UI Design" section for mockups
- Header format: `w[0/6] o[0/2]` = workers active/total, orchestrators active/total

## Slices

### Slice 6.2.1: Layout Constraints

**Do this**:
- Create `src/tui/layout.rs`
- Define `AppLayout` struct that holds the three areas (header, main, input)
- Implement `AppLayout::new(area: Rect) -> Self` that calculates sub-areas
- Use `ratatui::layout::Layout` with constraints:
  - Header: `Constraint::Length(1)` - exactly 1 line
  - Main: `Constraint::Min(1)` - takes remaining space
  - Input: `Constraint::Length(2)` - exactly 2 lines
- Export from `src/tui/mod.rs`

**Create/modify**:
- `src/tui/layout.rs`
- `src/tui/mod.rs`

**Code example**:
```rust
// src/tui/layout.rs
use ratatui::layout::{Constraint, Direction, Layout, Rect};

pub struct AppLayout {
    pub header: Rect,
    pub main: Rect,
    pub input: Rect,
}

impl AppLayout {
    pub fn new(area: Rect) -> Self {
        let chunks = Layout::default()
            .direction(Direction::Vertical)
            .constraints([
                Constraint::Length(1),  // header
                Constraint::Min(1),     // main content
                Constraint::Length(2),  // input bar
            ])
            .split(area);

        Self {
            header: chunks[0],
            main: chunks[1],
            input: chunks[2],
        }
    }
}
```

**Verify**:
- [ ] `cargo check` passes
- [ ] `AppLayout::new()` compiles and returns valid Rects
- [ ] Constraints sum correctly (header 1 + input 2 + flexible main)

### Slice 6.2.2: Header Bar Widget

**Do this**:
- Create header bar component that displays:
  - Left side: Agent status `w[0/6] o[0/2]`
  - Right side: Current view name (e.g., `/home`, `/feed`)
- Create `HeaderBar` struct with `workers_active`, `workers_total`, `orchestrators_active`, `orchestrators_total`, `current_view` fields
- Implement `Widget` trait for `HeaderBar`
- Use horizontal layout to position left and right content

**Create/modify**:
- `src/tui/layout.rs` - add `HeaderBar` struct and Widget impl

**Code example**:
```rust
// src/tui/layout.rs
use ratatui::{
    buffer::Buffer,
    layout::Rect,
    style::{Color, Style},
    text::{Line, Span},
    widgets::Widget,
};

pub struct HeaderBar {
    pub workers_active: u8,
    pub workers_total: u8,
    pub orchestrators_active: u8,
    pub orchestrators_total: u8,
    pub current_view: String,
}

impl Default for HeaderBar {
    fn default() -> Self {
        Self {
            workers_active: 0,
            workers_total: 6,
            orchestrators_active: 0,
            orchestrators_total: 2,
            current_view: "/home".to_string(),
        }
    }
}

impl Widget for HeaderBar {
    fn render(self, area: Rect, buf: &mut Buffer) {
        let status = format!(
            "w[{}/{}] o[{}/{}]",
            self.workers_active, self.workers_total,
            self.orchestrators_active, self.orchestrators_total
        );

        // Render status on left
        buf.set_string(area.x, area.y, &status, Style::default());

        // Render view name on right
        let view_x = area.right().saturating_sub(self.current_view.len() as u16);
        buf.set_string(view_x, area.y, &self.current_view, Style::default().fg(Color::DarkGray));
    }
}
```

**Verify**:
- [ ] `cargo check` passes
- [ ] HeaderBar renders status on left, view name on right

### Slice 6.2.3: Input Bar Widget

**Do this**:
- Create `InputBar` struct to hold current input text and cursor position
- Implement `Widget` trait for `InputBar`
- Display prompt `> ` followed by input text
- Show a visual cursor indicator (e.g., `_` or block)
- Second line reserved for status/hints (can be empty for now)

**Create/modify**:
- `src/tui/input.rs` - create input bar component
- `src/tui/mod.rs` - export input module
- `src/tui/app.rs` - integrate layout and widgets into render loop

**Code example**:
```rust
// src/tui/input.rs
use ratatui::{
    buffer::Buffer,
    layout::Rect,
    style::{Color, Style},
    widgets::Widget,
};

pub struct InputBar {
    pub input: String,
    pub cursor_position: usize,
}

impl Default for InputBar {
    fn default() -> Self {
        Self {
            input: String::new(),
            cursor_position: 0,
        }
    }
}

impl Widget for InputBar {
    fn render(self, area: Rect, buf: &mut Buffer) {
        // First line: prompt and input
        let prompt = "> ";
        buf.set_string(area.x, area.y, prompt, Style::default());
        buf.set_string(
            area.x + prompt.len() as u16,
            area.y,
            &self.input,
            Style::default(),
        );

        // Cursor indicator
        let cursor_x = area.x + prompt.len() as u16 + self.cursor_position as u16;
        if cursor_x < area.right() {
            buf.set_string(cursor_x, area.y, "_", Style::default().fg(Color::Gray));
        }

        // Second line: hints/status (empty for now)
    }
}
```

- **Agent counts**: For now, hardcode defaults. Will be connected to real agent pool in 6.5.
- **Cursor handling**: The visual cursor `_` is separate from the terminal's actual cursor. We hide the real cursor in TUI mode.
- **Input handling**: Actual text input handling is in 6.3 (Home Screen) when we transition to chat.
- **Color scheme**: Keep minimal for now. Can enhance in M9 polish phase.
