# Ticket 6.3: Home Screen

> Startup/idle view with branding and transition to chat.

## Goal

Create the home screen that users see on startup:
- Centered ASCII art logo
- System status messages at bottom
- Transitions to chat view when user starts typing

**Checkpoint**: `cargo run` shows nexor logo centered, and typing any character transitions to chat input.

---

## Context

The home screen is the "landing page" of the TUI. It shows branding and waits for user input. As soon as the user types, we transition to the chat view (or handle slash commands).

**Key files**:
- `src/tui/views/mod.rs` - Views module root (create)
- `src/tui/views/home.rs` - Home screen view (create)
- `src/tui/app.rs` - Add view state management (modify)

**Dependencies**:
- Requires 6.2 (Layout System) complete

```rust
// src/tui/views/mod.rs
mod home;

pub use home::HomeView;

// src/tui/views/home.rs
use ratatui::{
    buffer::Buffer,
    layout::{Alignment, Rect},
    style::{Color, Style},
    text::{Line, Text},
    widgets::{Paragraph, Widget},
};

const LOGO: &str = r#"

 ███╗   ██╗███████╗██╗  ██╗ ██████╗ ██████╗
 ████╗  ██║██╔════╝╚██╗██╔╝██╔═══██╗██╔══██╗
 ██╔██╗ ██║█████╗   ╚███╔╝ ██║   ██║██████╔╝
 ██║╚██╗██║██╔══╝   ██╔██╗ ██║   ██║██╔══██╗
 ██║ ╚████║███████╗██╔╝ ██╗╚██████╔╝██║  ██║
 ╚═╝  ╚═══╝╚══════╝╚═╝  ╚═╝ ╚═════╝ ╚═╝  ╚═╝

"#;

pub struct HomeView {
    pub status_message: Option<String>,
}

impl Default for HomeView {
    fn default() -> Self {
        Self {
            status_message: None,
        }
    }
}

impl Widget for HomeView {
    fn render(self, area: Rect, buf: &mut Buffer) {
        // Calculate vertical centering
        let logo_lines: Vec<&str> = LOGO.lines().collect();
        let logo_height = logo_lines.len() as u16;
        let start_y = area.y + (area.height.saturating_sub(logo_height)) / 2;

        // Render logo centered
        for (i, line) in logo_lines.iter().enumerate() {
            let y = start_y + i as u16;
            if y >= area.bottom() {
                break;
            }
            let x = area.x + (area.width.saturating_sub(line.len() as u16)) / 2;
            buf.set_string(x, y, line, Style::default().fg(Color::Cyan));
        }
    }
}
```

### Slice 6.3.2: View State Management

**Do this**:
- Add `CurrentView` enum to track which view is active
- Add `current_view` field to `App` struct
- Update render loop to render different views based on state
- Start with `CurrentView::Home` as default

**Create/modify**:
- `src/tui/app.rs` - add view state and conditional rendering

**Code example**:
```rust
// src/tui/app.rs
use crate::tui::views::HomeView;

#[derive(Debug, Clone, PartialEq)]
pub enum CurrentView {
    Home,
    Chat,
    Feed,
    Logs,
}

impl CurrentView {
    pub fn as_str(&self) -> &'static str {
        match self {
            CurrentView::Home => "/home",
            CurrentView::Chat => "/main",
            CurrentView::Feed => "/feed",
            CurrentView::Logs => "/logs",
        }
    }
}

pub struct App {
    should_quit: bool,
    current_view: CurrentView,
    input_buffer: String,
}

impl App {
    pub fn new() -> Self {
        Self {
            should_quit: false,
            current_view: CurrentView::Home,
            input_buffer: String::new(),
        }
    }

    pub fn run(&mut self, terminal: &mut Tui) -> io::Result<()> {
        while !self.should_quit {
            terminal.draw(|frame| {
                let layout = AppLayout::new(frame.area());

                // Header with current view
                let header = HeaderBar {
                    current_view: self.current_view.as_str().to_string(),
                    ..HeaderBar::default()
                };
                frame.render_widget(header, layout.header);

                // Render current view in main area
                match self.current_view {
                    CurrentView::Home => {
                        let home = HomeView::default();
                        frame.render_widget(home, layout.main);
                    }
                    _ => {
                        // Placeholder for other views
                        let placeholder = Paragraph::new(format!("{} view", self.current_view.as_str()));
                        frame.render_widget(placeholder, layout.main);
                    }
                }

                // Input bar
                let input = InputBar {
                    input: self.input_buffer.clone(),
                    cursor_position: self.input_buffer.len(),
                };
                frame.render_widget(input, layout.input);
            })?;

            // Event handling (existing code)
            // ...
        }
        Ok(())
    }
}
```

### Slice 6.3.3: Transition to Chat on Typing

**Do this**:
- Handle character input events in the event loop
- When user types any printable character on home screen:
  - Switch `current_view` to `CurrentView::Chat`
  - Add the typed character to `input_buffer`
- Handle backspace to remove characters from buffer
- Slash commands (starting with `/`) will be handled in 6.6

**Create/modify**:
- `src/tui/app.rs` - add character handling in event loop

**Code example**:
```rust
// src/tui/app.rs - in the event handling section
if event::poll(Duration::from_millis(100))? {
    if let Event::Key(key) = event::read()? {
        match key.code {
            KeyCode::Char('c') if key.modifiers.contains(KeyModifiers::CONTROL) => {
                self.should_quit = true;
            }
            KeyCode::Char(c) => {
                // Transition from home to chat on first keypress
                if self.current_view == CurrentView::Home {
                    self.current_view = CurrentView::Chat;
                }
                self.input_buffer.push(c);
            }
            KeyCode::Backspace => {
                self.input_buffer.pop();
                // If buffer empty and in chat, could go back to home
                // (optional behavior, can skip for now)
            }
            KeyCode::Enter => {
                // Will be handled in 6.5 (Chat) and 6.6 (Commands)
                // For now, just clear the buffer
                self.input_buffer.clear();
            }
            KeyCode::Esc => {
                // Return to home screen
                self.current_view = CurrentView::Home;
                self.input_buffer.clear();
            }
            _ => {}
        }
    }
}
```

## Notes

- **Logo choice**: The example uses block characters. Adjust as needed for terminal compatibility.
- **Color**: Cyan for logo is a suggestion. Can be configured later.
- **Transition behavior**: Typing immediately adds character to buffer AND switches view. This feels responsive.
- **Esc key**: Returns to home. This is a safe "reset" action.
- **Status messages**: The `status_message` field in HomeView is for future use (e.g., "Connected to database", "Loading...").
