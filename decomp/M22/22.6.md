# Ticket 22.6: Container Pool Integration

> Wire container lifecycle into the agent pool so the orchestrator can seamlessly spawn containerized agents.

## Goal

`ContainerPool` orchestrates the full flow: create worktree, spawn container, connect worker client, assign task, collect result, merge back, cleanup. Integrates with existing `AgentPool` so the orchestrator doesn't need to know whether agents are in-process or containerized.

### 22.6.2: spawn_containerized_agent

Full lifecycle: worktree + container + client.

```rust
pub async fn spawn(
    &mut self,
    task_id: Uuid,
    branch: &str,
    description: &str,
) -> Result<String, ContainerPoolError>;
```

Steps:
1. `worktree_manager.create(agent_id, branch)`
2. `spawn_container(agent_id, worktree_path, config)`
3. `wait_for_healthy(container, timeout)`
4. `WorkerClient::connect(agent_id, ws_url)`
5. `client.assign_task(task_id, description, branch)`

**Test**: Verify all 5 steps are called in sequence.

### 22.6.3: collect_and_merge

When a task completes, merge the worktree branch back.

```rust
pub async fn collect_and_merge(
    &mut self,
    agent_id: &str,
) -> Result<MergeResult, ContainerPoolError>;
```

Steps:
1. `client.await_result(timeout)`
2. If success: `git merge` from worktree branch into target branch (using existing `GitOps`)
3. Cleanup: stop container, remove worktree

**Test**: Successful task triggers merge and cleanup.

### 22.6.4: Graceful degradation

When Docker is unavailable, fall back to in-process execution:

```rust
pub async fn spawn_or_fallback(
    &mut self,
    task_id: Uuid,
    branch: &str,
    description: &str,

pub enum ExecutionMode {
    Container { agent_id: String },
    InProcess,  // Docker unavailable, running locally
}
```
