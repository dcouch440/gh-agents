# Ticket 22.3: Container Lifecycle Management

> Spawn, monitor, and destroy Docker containers for agent workers.

## Goal

`AgentContainer` and container lifecycle functions that create Docker containers from the worker image, mount worktrees, and manage start/stop. Builds on existing `Sandbox` patterns but for long-running agent processes rather than one-shot commands.

## Slices

### 22.3.1: ContainerConfig and ContainerStatus types

```rust
pub struct ContainerConfig {
    pub image: String,                    // "nexor-worker:latest"
    pub memory_limit: String,             // "2g"
    pub cpu_limit: String,                // "2.0"
    pub network_enabled: bool,            // true (need git push)
    pub env_vars: Vec<(String, String)>,  // NEXOR_ORCHESTRATOR_URL, etc.
    pub orchestrator_url: String,         // ws://host:3000/ws/worker
    pub health_check_port: u16,           // 3001
}

pub enum ContainerStatus {
    Creating,
    Running { container_id: String },
    Stopped { exit_code: i32 },
    Failed { error: String },
}

pub struct AgentContainer {
    pub agent_id: String,
    pub container_name: String,
    pub worktree_path: PathBuf,
    pub branch: String,
    pub status: ContainerStatus,
    pub created_at: chrono::DateTime<chrono::Utc>,
}
```

**Test**: Types construct correctly, status transitions are valid.

### 22.3.2: spawn_container

Launch a Docker container for an agent with its worktree mounted.

```rust
pub async fn spawn_container(
    agent_id: &str,
    worktree_path: &Path,
    config: &ContainerConfig,
) -> Result<AgentContainer, ContainerError>;
```

Runs `docker run -d` with:
- `--name nexor-agent-<agent_id>`
- `--volume <worktree_path>:/workspace:rw`
- Resource limits from config
- Environment variables (orchestrator URL, agent ID)
- Health check: `curl -f http://localhost:<port>/health`

**Test**: Mock docker command execution, verify correct args are passed.

### 22.3.3: stop_container
