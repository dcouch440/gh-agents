# Ticket 18.7: Observability

> Track subagent lifecycle in feed and analytics.

## Goal

Subagent spawn/complete events appear in the activity feed. Ephemeral agent costs roll up to the parent task. A delegation tree endpoint shows parent→child relationships. Pool stats include ephemeral counts.

**Checkpoint**: Feed shows "Spawned explorer subagent" and "Explorer completed: found 3 auth files". `GET /api/tasks/:id/delegation-tree` returns parent→child agent tree. `PoolStats` includes `ephemeral_active` count.

---

## Context

Without observability, subagent activity is invisible to the user. This ticket makes subagent lifecycle visible in the feed, traceable in cost reports, and queryable via API.

**Key files**:
- `src/server/ws.rs` — Feed event types (already partially done in 18.6)
- `src/agents/pool.rs` — Extended `PoolStats`
- `src/server/api.rs` — Delegation tree endpoint
- `src/llm/cost.rs` — Cost aggregation

**Dependencies**: 18.2, 18.5

---

## Slices

### Slice 18.7.1: Feed Events

**Do this**:
- When a subagent is spawned, broadcast a `FeedUpdate` with:
  - `item_type: "subagent_spawned"`
  - `content`: "Spawned {agent_type} subagent for: {task_title}"
  - `agent_id`: parent agent ID (or "system" if manual spawn)
- When a subagent completes, broadcast a `FeedUpdate` with:
  - `item_type: "subagent_completed"`
  - `content`: "{agent_type} completed: {summary}" or "{agent_type} failed: {error}"
  - `agent_id`: child agent ID
- Use `state.broadcast_feed()` for broadcasting

**Verify**:
- [ ] Spawn event appears in feed with correct `item_type`
- [ ] Completion event appears in feed
- [ ] Failure event includes error message
- [ ] Feed subscribers receive events in real-time

---

### Slice 18.7.2: Cost Aggregation

**Do this**:
- In `CostTracker`, add `cost_for_task_with_children(task_id: &TaskId) -> f64`:
  - Sum costs for the parent task AND all subagent tasks that reference the same parent task
  - This requires ephemeral agents to record their `task_id` when calling the LLM
- Add a `parent_task_id: Option<TaskId>` field to `CostRecord` to track delegation
- Update `CostSummary` to include `by_task` entries that aggregate child costs

**Verify**:
- [ ] Parent task cost includes its own LLM calls
- [ ] Parent task cost includes child subagent LLM calls
- [ ] `cost_for_task_with_children` returns total > individual parent cost
- [ ] Cost breakdown shows per-child contributions

---

### Slice 18.7.3: Delegation Tree Endpoint

**Do this**:
- Add `GET /api/tasks/:id/delegation-tree` endpoint
- Add `DelegationNode` struct:
  - `agent_id: String`
  - `agent_type_id: Option<String>`
  - `tier: String`
  - `status: String`
  - `task_title: String`
  - `children: Vec<DelegationNode>`
- Build tree from spawn tracking data:
  - Track parent→child relationships when subagents are spawned
  - Store in memory (e.g., `HashMap<Uuid, Vec<(AgentId, AgentTypeId)>>` in `AppState`)
- Return 200 with tree, or 404 if task not found

**Verify**:
- [ ] Task with 3 subagents → tree has root + 3 children
- [ ] Task with no subagents → tree has root only, empty children
- [ ] Non-existent task → 404
- [ ] Tree serializes correctly as JSON

---

### Slice 18.7.4: PoolStats Extension

**Do this**:
- Add fields to `PoolStats`:
  - `ephemeral_active: usize` — currently running ephemeral agents
  - `ephemeral_total: usize` — total ephemeral agents spawned in session
  - `by_type: HashMap<String, usize>` — active ephemeral count per agent type
- Update `AgentPool::stats()` to populate the new fields
- Track `ephemeral_total` as a running counter in `AgentPool`
- Update `AgentPoolStats` in `api.rs` to include ephemeral fields in the response

**Verify**:
- [ ] `ephemeral_active` reflects current count
- [ ] `ephemeral_total` only increases (never decrements)
- [ ] `by_type` shows correct count per type (e.g., `{"explorer": 2, "coder": 1}`)
- [ ] `GET /api/agents` response includes ephemeral stats
- [ ] Stats are accurate after spawns and cleanups
