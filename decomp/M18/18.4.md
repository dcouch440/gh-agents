# Ticket 18.4: Orchestrator Subagent Spawning

> Orchestrator analyzes tasks and spawns appropriate typed subagents.

## Goal

A `SubagentSpawner` creates ephemeral agents from `SpawnRequest`s. A `TaskAnalyzer` uses an LLM call to decide which subagent types a complex task needs. The orchestrator executor integrates both — complex tasks trigger analysis and spawning, simple tasks bypass it.

**Checkpoint**: Given a complex task like "refactor auth module with tests", the orchestrator spawns Coder + Tester subagents. A simple task like "fix typo in README" executes directly without spawning.

---

This ties together the registry (18.1), ephemeral lifecycle (18.2), and protocol (18.3) into actual orchestrator behavior.

## Slices

### Slice 18.4.1: SubagentSpawner

**Do this**:
- Create `src/agents/spawner.rs`
- Add `SubagentSpawner` struct holding references to:
  - `AgentTypeRegistry`
  - `AgentPool` (via `Arc<RwLock<AgentPool>>` or passed mutably)
  - `Dispatcher` (via `Arc<RwLock<Dispatcher>>`)
  - LLM provider
- Implement `spawn_for_task(SpawnRequest) -> Result<AgentId, AgentTypeError>`:
  - Look up `AgentType` from registry
  - Build `AgentPersona` from the agent type's role
  - Get `ModelConfig` from tier models config
  - Call `pool.spawn_ephemeral_with_dispatcher()`
  - Send `AgentCommand::AssignTask` to the new agent via dispatcher
  - Return the new agent's ID

**Verify**:
- [ ] `spawn_for_task` creates an ephemeral agent of the correct type and tier
- [ ] Returns `AgentTypeError::NotFound` for unknown type IDs
- [ ] Returns `EphemeralLimitReached` when pool is full
- [ ] Agent receives the task assignment

### Slice 18.4.2: TaskAnalyzer

**Do this**:
- Add `TaskAnalyzer` struct holding an LLM provider reference
- Implement `analyze(task_title: &str, task_description: &str) -> Result<Vec<SpawnRecommendation>>`:
  - Build a system prompt that lists available agent types and their capabilities
  - Ask the LLM to return structured JSON: `[{"agent_type_id": "...", "title": "...", "description": "...", "priority": N}]`
  - Parse the JSON response into `Vec<SpawnRecommendation>`
- Add `complexity_score(title: &str, description: &str) -> u8`:
  - Simple heuristic: word count, keyword detection ("refactor", "test", "implement", "migrate")
  - Returns 0-100; used to decide if analysis is needed

**Verify**:
- [ ] With mock LLM returning valid JSON: parses into `Vec<SpawnRecommendation>`
- [ ] Code task → recommendations include Coder + Tester
- [ ] Explore task → recommendations include Explorer
- [ ] Invalid JSON from LLM → returns error (or empty vec with warning)

### Slice 18.4.3: LLM Analysis Prompt

### Slice 18.4.4: Orchestrator Integration

**Do this**:
- In `executor.rs`, modify orchestrator-tier agent behavior:
  - When an orchestrator receives `AssignTask`:
    1. Run `TaskAnalyzer::complexity_score()` on the task
    2. If score > threshold (e.g., 40), call `TaskAnalyzer::analyze()`
    3. Convert recommendations into `SpawnRequest`s
    4. Send `AgentCommand::SpawnSubagent` for each (or call spawner directly)
  - This requires detecting that `self.tier == AgentTier::Orchestrator`
- The orchestrator should track spawned child IDs so it can collect results later (store in a local `Vec<AgentId>`)

**Verify**:
- [ ] Orchestrator spawns subagents for complex tasks
- [ ] Orchestrator sends `SubagentSpawned` response for each spawned agent
- [ ] Child agent IDs are tracked

---

### Slice 18.4.5: Simple Task Bypass

**Do this**:
- Tasks with `complexity_score <= 40` skip the analysis step entirely
- The orchestrator executes them directly using the existing `execute_task` flow
- Tasks with `complexity_score > 40` go through the subagent spawning path

**Verify**:
- [ ] Simple task "fix typo" → executes directly, no subagents spawned
- [ ] Complex task "refactor and test auth" → analysis runs, subagents spawned
- [ ] Threshold is configurable (or at least a named constant)
