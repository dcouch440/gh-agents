# Ticket 23.10: CLI Navigation & Integration

> Screen state machine connecting chat, tree overlay, and gate views.

## Goal

The CLI App component manages a screen state machine that switches between chat, tree overlay, and gate conversation views. Global hotkeys toggle between screens.

**Checkpoint**: Run CLI → chat view → press `t` → tree overlay appears → select gate → gate view opens → resolve → back to tree → press Esc → back to chat.

---

## Context

Currently the CLI has a simple auth state machine (checking → login → authenticated/chat). This ticket adds a second layer: once authenticated, the user can switch between chat, tree, and gate screens.

**Dependencies**:

## Slices

### Slice 23.10.1: Screen State Machine

**Do this**:
- Define screen types for the authenticated state
- Add screen state to the App component
- The tree overlay renders ON TOP of chat (chat stays mounted underneath so it doesn't lose state)

**Modify `cli/src/App.tsx`**:
```tsx
type Screen =
  | { type: 'chat' }
  | { type: 'tree' }
  | { type: 'gate'; gateId: string };

export function App({ serverUrl }: AppProps) {
  const [authState, setAuthState] = useState<AuthState>('checking');
  const [screen, setScreen] = useState<Screen>({ type: 'chat' });

  // ... existing auth logic

  const renderAuthenticatedView = () => {
    return (
      <Box flexDirection="column" height="100%">
        {/* Chat is always mounted (hidden when overlay is active) */}
        {screen.type === 'chat' && <ChatView />}

        {/* Tree overlay covers the screen */}
        {screen.type === 'tree' && (
          <TreeOverlay
            onSelectGate={(gateId) => setScreen({ type: 'gate', gateId })}
            onClose={() => setScreen({ type: 'chat' })}
          />
        )}

        {/* Gate view replaces tree */}
        {screen.type === 'gate' && (
          <GateView
            gateId={screen.gateId}
            onClose={() => setScreen({ type: 'tree' })}
          />
        )}
      </Box>
    );
  };

  // ... render based on auth state
}
```

**Verify**:
- [ ] Screen transitions work: chat → tree → gate → tree → chat
- [ ] Chat view state preserved when returning from tree
- [ ] No component crashes during transitions

### Slice 23.10.2: Global Hotkeys

**Do this**:
- Add global keyboard handler for screen switching
- `t` toggles the tree overlay (from chat), or closes it (from tree)
- `Esc` goes back one level: gate → tree → chat
- Hotkeys should only fire when not typing in an input field
- Handle edge case: `t` pressed while in gate view should be ignored (typing in input)

**Add to `cli/src/App.tsx`**:
```tsx
useInput((input, key) => {
  // Only handle global hotkeys when not in an input-focused state
  if (input === 't' && screen.type === 'chat') {
    setScreen({ type: 'tree' });
  }
  // Esc handling is done per-component (tree and gate handle their own Esc)
});
```

**Verify**:
- [ ] `t` opens tree from chat
- [ ] `t` does not interfere when typing in gate input
- [ ] Esc chain works: gate → tree → chat
- [ ] No double-handling of key events

### Slice 23.10.3: Navigation Bar

**Do this**:
- Add a persistent navigation bar at the bottom of every screen
- Shows available actions based on current screen
- Consistent placement across all views

**Add navigation bar component**:
```tsx
function NavBar({ screen }: { screen: Screen }) {
  return (
    <Box marginTop={1} borderStyle="single" borderTop borderBottom={false} borderLeft={false} borderRight={false}>
      <Text dimColor>
        {screen.type === 'chat' && 't: Tree View │ Ctrl+C: Exit'}
        {screen.type === 'tree' && 'Enter: Open │ s: Skip │ Esc: Chat │ Ctrl+C: Exit'}
        {screen.type === 'gate' && 'Ctrl+R: Resolve │ Ctrl+S: Skip │ Esc: Tree │ Ctrl+C: Exit'}
      </Text>
    </Box>
  );
}
```
