# Ticket 19.1: Tool Execution Events Backend

> Emit structured, typed events from the agent toolkit whenever a tool is called — giving the frontend everything it needs to render tool calls without parsing text.

## Goal

When `AgentToolkit::execute()` runs a tool, it emits a `ToolCallStarted` event before execution and a `ToolCallCompleted` event after. These events carry structured data: tool name, typed arguments, typed output, duration, success/failure. They flow through the existing broadcast infrastructure to reach WebSocket subscribers.

**Checkpoint**: Agent executes `Read { path: "src/main.rs" }` → backend emits `ToolCallStarted` with tool name + args → tool runs → backend emits `ToolCallCompleted` with output + duration. Both events carry the `agent_id` and a unique `tool_call_id`.

---

## Context

The agent toolkit (18.9) executes tools but produces no observable side effects beyond the `ToolResult` fed back to the LLM. The UI has no way to know what tools are being called, what arguments they received, or what they returned.

**Key files**:
- `src/agents/toolkit.rs` — Emit events around tool execution
- New `src/agents/tool_events.rs` — Event types and builder
- `src/server/state.rs` — New broadcast channel for tool events
- `src/server/ws.rs` — New ServerMessage variants

**Dependencies**: 18.9 (AgentToolkit)

## Slices

### Slice 19.1.1: ToolCallEvent Types

**Do this**:
- Create `src/agents/tool_events.rs`
- Define `ToolCallId(Uuid)` newtype
- Define `ToolCallStarted` struct:
  - `tool_call_id: ToolCallId`
  - `agent_id: AgentId`
  - `agent_type_id: Option<String>` (e.g., "explorer", "coder")
  - `task_id: Option<Uuid>`
  - `tool_name: String` (e.g., "Read", "Grep", "Bash")
  - `tool_args: serde_json::Value` (structured args, e.g., `{"path": "src/main.rs"}`)
  - `timestamp: DateTime<Utc>`
- Define `ToolCallCompleted` struct:
  - `tool_call_id: ToolCallId` (matches the started event)
  - `agent_id: AgentId`
  - `tool_name: String`
  - `success: bool`
  - `output: ToolCallOutput`
  - `error: Option<String>`
  - `duration_ms: u64`
  - `timestamp: DateTime<Utc>`
- Define `ToolCallOutput` enum:
  - `Text(String)` — plain text output (Read file content, Bash stdout)
  - `FileList(Vec<String>)` — Glob results
  - `SearchMatches(Vec<SearchMatchData>)` — Grep results with line numbers, context
  - `Diff { path: String, old_content: String, new_content: String, replacements: usize }` — Edit/Write changes
  - `Empty` — tools that produce no meaningful output
- `SearchMatchData`: `file: String`, `line_number: usize`, `line_content: String`, `context_before: Vec<String>`, `context_after: Vec<String>`
- Derive `Serialize, Deserialize, Clone` on all types

**Verify**:
- [ ] All event types serialize to JSON
- [ ] `ToolCallOutput` variants cover Read, Write, Edit, Glob, Grep, Bash, Git
- [ ] `ToolCallId` roundtrip serde works

### Slice 19.1.3: Emit Events from AgentToolkit

**Do this**:
- Add `tool_event_tx: broadcast::Sender<ToolCallEvent>` to `AgentToolkit`
- In `AgentToolkit::execute()`:
  1. Generate a `ToolCallId`
  2. Build `ToolCallStarted` from the `AgentTool` variant (extract tool name + args as JSON)
  3. Send `ToolCallStarted` via `tool_event_tx`
  4. Execute the tool (existing dispatch logic)
  5. Build `ToolCallCompleted` with output converted to `ToolCallOutput`, duration measured
  6. Send `ToolCallCompleted` via `tool_event_tx`
- Convert each tool's result to the appropriate `ToolCallOutput` variant:
  - `Read` → `Text(file_content)`
  - `Write` → `Diff { path, old: "", new: content, replacements: 0 }`
  - `Edit` → `Diff { path, old_content, new_content, replacements }`
  - `Glob` → `FileList(paths)`
  - `Grep` → `SearchMatches(matches)`
  - `Bash` → `Text(stdout + stderr)`
  - `GitStatus` → `Text(status_output)`
  - `GitDiff` → `Text(diff_output)` or `Diff` if structured
  - `GitCommit` → `Text(commit_hash)`
  - `RunTests` → `Text(test_output)`

**Verify**:
- [ ] Read tool → `Started` event with `{"path": "..."}` args, `Completed` with `Text` output
- [ ] Glob tool → `Completed` with `FileList` output
- [ ] Grep tool → `Completed` with `SearchMatches` output
- [ ] Edit tool → `Completed` with `Diff` output showing before/after
- [ ] Failed tool → `Completed` with `success: false` and `error` message
- [ ] Duration is accurately measured

### Slice 19.1.5: Output Truncation

**Do this**:
- Add truncation to `ToolCallOutput` before sending events:
  - `Text` → truncate to 50,000 chars, append `"\n... (truncated, {total} chars total)"`
  - `FileList` → truncate to 500 items, note total count
  - `SearchMatches` → truncate to 100 matches, note total count
  - `Diff` → truncate old/new content to 50,000 chars each
- Add `truncated: bool` and `total_size: Option<usize>` fields to `ToolCallCompleted`
- Truncation happens at the event emission layer, not the execution layer (tools still return full results for LLM consumption)

**Verify**:
- [ ] 100KB file read → event output truncated to 50K chars with note
- [ ] 2000 glob results → event shows 500 with "2000 total" note
- [ ] Small outputs are not truncated
- [ ] `truncated` flag is accurate
