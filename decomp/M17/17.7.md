# Ticket 17.7: Test Infrastructure

> Replace SQLite test databases with per-test Postgres databases.

## Goal

All tests run against real Postgres databases. Each test gets an isolated database that is created before and dropped after the test.

**Checkpoint**: `cargo test` passes with all tests running against Postgres.

---

## Context

Currently, tests use `tempfile::TempDir` to create ephemeral SQLite databases. The Postgres equivalent is creating a temporary database per test via `CREATE DATABASE`, running the test, then `DROP DATABASE` on teardown.

**Key files**:
- `src/db/mod.rs` (or a new `src/db/test_utils.rs`) — Test database helper
- All `#[cfg(test)]` modules that create database connections
- `Cargo.toml` — Remove `tempfile` dev-dependency if no longer needed

**Dependencies**: 17.6 (all code must compile first)

---

## Slices

### Slice 17.7.1: Test Database Helper

**Do this**:
- Create a `TestDb` struct that:
  - Connects to the Postgres instance using `DATABASE_URL` (or default)
  - Creates a uniquely-named database: `nexor_test_{uuid}`
  - Runs all migrations on it
  - Returns a `PgPool` connected to the test database
  - Implements `Drop` to drop the test database (or provide an async cleanup method)
- Use a connection to the default `nexor` database to run `CREATE DATABASE` / `DROP DATABASE`

```rust
pub struct TestDb {
    pub pool: PgPool,
    db_name: String,
    admin_pool: PgPool,
}

impl TestDb {
    pub async fn new() -> Self { /* ... */ }
    pub async fn cleanup(self) { /* ... */ }
}
```

**Verify**:
- [ ] `TestDb::new()` creates a fresh database with migrations applied
- [ ] `cleanup()` drops the database
- [ ] Multiple `TestDb` instances can coexist (unique names)
