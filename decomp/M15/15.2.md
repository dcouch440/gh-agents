# Ticket 15.2: Prompt Library Backend

> Database schema and API for storing, versioning, tagging, and launching saved prompts.

## Goal

Users can save reusable prompts, organize them with tags/categories, track versions, and quick-launch them into agent chat sessions.

**Checkpoint**: Can CRUD prompts via API, tag them, retrieve version history, and launch a prompt to start a chat.

---

## Context

Prompts are currently hardcoded in `src/prompts/`. This ticket adds a user-facing prompt library — saved templates that users create and reuse.

**Key files**:
- `src/server/api.rs` — API endpoints
- `src/db/mod.rs` — Database queries
- `migrations/` — New migration

**Dependencies**:
- Requires M10 (Server Layer) complete

## Slices

### Slice 15.2.1: Database Schema

**Do this**:
- Create migration `008_prompts.sql`:
  - `prompts` table: `id`, `title`, `content`, `category`, `repo_id` (nullable FK), `is_global` (BOOLEAN), `created_at`, `updated_at`
  - `prompt_tags` table: `prompt_id`, `tag` (TEXT), composite PK
  - `prompt_versions` table: `id`, `prompt_id` (FK), `content`, `version_num`, `created_at`
- DB functions: `insert_prompt`, `get_prompt`, `list_prompts`, `update_prompt`, `delete_prompt`
- On update, auto-create version entry with previous content

### Slice 15.2.2: Prompt CRUD API

**Do this**:
- `POST /api/prompts` — Create prompt (body: `{ title, content, category?, tags?, repo_id? }`)
- `GET /api/prompts` — List prompts (query params: `?category=&tag=&repo_id=&search=`)
- `GET /api/prompts/:id` — Get prompt with tags
- `PUT /api/prompts/:id` — Update prompt (auto-versions)
- `DELETE /api/prompts/:id` — Delete prompt and versions

## Notes

- Prompts can be global (available in all repos) or repo-scoped
- Categories are freeform strings, not a separate table
- Template variables use `{{double_braces}}` syntax to avoid conflicts with markdown
