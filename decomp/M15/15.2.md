# Ticket 15.2: Prompt Library Backend

> Database schema and API for storing, versioning, tagging, and launching saved prompts.

## Goal

Users can save reusable prompts, organize them with tags/categories, track versions, and quick-launch them into agent chat sessions.

**Checkpoint**: Can CRUD prompts via API, tag them, retrieve version history, and launch a prompt to start a chat.

---

## Context

Prompts are currently hardcoded in `src/prompts/`. This ticket adds a user-facing prompt library — saved templates that users create and reuse.

**Key files**:
- `src/server/api.rs` — API endpoints
- `src/db/mod.rs` — Database queries
- `migrations/` — New migration

**Dependencies**:
- Requires M10 (Server Layer) complete

### Slice 15.2.5: Variable Resolution Engine

**Do this**:
- Create `src/prompts/variables.rs` — resolves `{{variable}}` tokens against live system state
- `GET /api/prompts/variables` — Returns all available variables with current values
- Variable registry with three source tiers:
  - **System context** (always available, auto-filled):
    - `{{repo}}` — active repo name
    - `{{repo_path}}` — active repo absolute path
    - `{{branch}}` — current git branch
    - `{{is_dirty}}` — true/false, has uncommitted changes
    - `{{staged_files}}` — comma-separated list of staged files
    - `{{unstaged_files}}` — comma-separated list of unstaged files
    - `{{autonomy}}` — FullAuto / ApprovalGates / Supervised
    - `{{git_strategy}}` — BranchPerSlice / BranchPerTicket
    - `{{verbosity}}` — Quiet / Normal / Verbose
  - **Task context** (auto-filled when launched from a task):
    - `{{task_title}}`, `{{task_description}}`, `{{task_priority}}`, `{{task_status}}`
    - `{{ticket_title}}`, `{{ticket_description}}`
    - `{{slice_title}}`
    - `{{context_files}}` — files relevant to the task
    - `{{assigned_tier}}` — Orchestrator / Worker / Utility
  - **Agent context** (auto-filled when an agent is selected):
    - `{{agent_name}}`, `{{agent_tier}}`, `{{agent_model}}`, `{{agent_status}}`
- Resolution function: `resolve_variables(template: &str, context: &LaunchContext) -> ResolvedPrompt`
  - Returns the substituted string + list of unresolved variables (for manual fill)
- Each variable has metadata: `{ key, description, source_tier, current_value, is_available }`

### Slice 15.2.6: Quick-Launch to Chat

**Do this**:
- `POST /api/prompts/:id/launch` — Resolve variables and send prompt as chat message
  - Body: `{ overrides?: { key: value }, task_id?: string, agent_id?: string }`
  - Auto-fills all available variables from system/task/agent context
  - Applies any manual overrides on top
  - Returns unresolved variables as errors if any remain after resolution
- Return the chat message ID for frontend to navigate to chat view

## Notes

- Prompts can be global (available in all repos) or repo-scoped
- Categories are freeform strings, not a separate table
- Template variables use `{{double_braces}}` syntax to avoid conflicts with markdown
- Variable resolution is context-aware: system vars always resolve, task/agent vars only resolve when that context exists
- The `/api/prompts/variables` endpoint lets the frontend show which variables are currently available and what their values are
