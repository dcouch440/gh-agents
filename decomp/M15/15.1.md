# Ticket 15.1: Multi-Repo Backend

> Database schema and API endpoints for managing multiple git repositories from a single nexor instance.

## Goal

Users can add, list, switch, remove, and configure multiple repositories. The active repo determines the file tree, git context, and agent workspace.

**Checkpoint**: Can `POST /api/repos` to add a repo, `GET /api/repos` to list them, `PATCH /api/repos/:id/activate` to switch, and all file/git operations scope to the active repo.

---

## Context

The existing `FileOps` and `GitOps` in `src/execution/` operate on a single working directory. This ticket adds a repo registry so the system can manage multiple directories.

**Key files**:
- `src/execution/files.rs` — File operations (needs repo-scoped paths)
- `src/execution/git.rs` — Git operations (needs repo-scoped working dir)
- `src/server/api.rs` — API endpoints
- `src/db/mod.rs` — Database queries
- `migrations/` — New migration for repos table

**Dependencies**:
- Requires M10 (Server Layer) complete

## Slices

### Slice 15.1.1: Database Schema

**Do this**:
- Create migration `007_repos.sql` with `repos` table:
  - `id` (TEXT PRIMARY KEY, UUID)
  - `name` (TEXT NOT NULL) — display name
  - `path` (TEXT NOT NULL UNIQUE) — absolute path on disk
  - `remote_url` (TEXT) — git remote origin
  - `is_active` (BOOLEAN NOT NULL DEFAULT 0)
  - `default_branch` (TEXT DEFAULT 'main')
  - `created_at`, `updated_at` (DATETIME)
- Add DB functions: `insert_repo`, `get_repo`, `list_repos`, `delete_repo`, `set_active_repo`
- `set_active_repo` must deactivate all others first (only one active)

**Create/modify**:
