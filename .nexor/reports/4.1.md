## Key Design Decisions

1. **Canonical Prompt Structure**: All prompts follow the skeleton: role, context, task, constraints, output_format, examples. Sections are omitted if empty.

2. **Budget Percentages**: Context injection uses fixed budget allocation:
   - Files to modify: 40%
   - Reference files: 25%
   - Task/history: 20%
   - Conventions: 15%

3. **Token Estimation**: Simple `len/4` placeholder - proper token counting deferred to Ticket 4.11.

4. **Semantic Versioning**: Prompts use family + semver (e.g., `decomposition-1.2.0`) for tracking which prompt version produced which output.

## Notes

- The `PromptBuilder` uses a fluent API pattern consistent with existing types (e.g., `TaskBuilder` in types).
- `PromptExecution` stores full prompt text and response for debugging/replay (supports future Ticket 9.6).
- `PromptRegistry.latest()` excludes deprecated versions, enabling safe prompt evolution.
- Context priority (0-255) allows fine-grained control over what gets included first.
